# Utility 聚类前沿单目标探索

项目只保留 Utility 探索。标准航点接口直接调用 Utility，随后执行现有 A* 路径、EGO 局部避障、安全检查和位置航点控制。

## 文件与入口

| 文件 | 内容 |
| --- | --- |
| `navigation/exploration_planner.py` | 标准航点接口及安全前向候选优先策略 |
| `navigation/utility_frontier_manager.py` | 前沿聚类、候选生成、A* 代价、评分与访问记忆 |
| `navigation/frontier_geometry.py` | 航点数据结构和遮挡射线信息增益 |
| `navigation/frontier_explorer.py` | 航点执行、恢复、覆盖终止、报告 |
| `config/frontier_decision_config.py` | Utility 评分、聚类与前向偏好参数 |
| `config/exploration_config.py` | 共用候选、飞行高度、预算及终止参数 |

## 实际决策流程

1. 从 `grid.known - grid.occupied`（完整机身高度带的原始自由格）查找邻接未知格的 FREE 格，使用 8 邻接。**不在已经净空收缩的 `grid.free` 上直接找前沿**，否则边界会被安全距离隔开。
2. BFS 生成连通片段。长连续边界按最大跨度拆为仍然连通的局部片段，避免整圈边界只有一个落在房间中央的质心。过滤少于 `min_frontier_size` 个格子的片段。
3. `FrontierCluster` 保存 id、cells、三维 centroid。相邻更新用前沿格重叠关联 ID；访问次数按候选航点从空间访问历史计算，因此前沿拆分、合并、消失重现不会简单清零访问次数。簇不再重复计算和缓存未参与评分的质心访问次数。
4. 每簇在质心周围采样，保留最多 4 个分散候选。必须位于现有安全栅格，距离处于 candidate_radius_min/max 范围，高度等于当前导航平面。受障碍限制时可少于 4 个，不补造不安全候选。Yaw 朝向质心。
5. 复用 `visible_unknown()` 的近似相机射线，统计视场和半径内未知格；已知障碍遮挡射线。这是当前飞行高度上的二维增益近似，不是复杂三维 NBV。
6. 对每个候选调用现有 `grid.path(current, viewpoint)`。无路径则丢弃；路径长度是 A* 返回的安全折线路程，**不是直线距离**。
7. `score_candidates()` 计算归一化评分。接口优先从安全前向候选中选点，没有合格前向候选时选择最高分目标。选定后的 `visit_order` 最多只有一个元素，不执行 ATSP/TSP 巡回。
8. 到达后记录一次区域访问；重规划、途经、失败和目标取消均不计为到达。重复访问只扣分，不永久屏蔽仍有未知区域的前沿。

## 评分和参数

评分位置：`navigation/utility_frontier_manager.py::score_candidates()`。

```text
Gain = 当前候选可见未知格数 / 本轮可达候选的最大未知格数
PathCost = min(A* 路长 / path_normalization_m, 1)
YawCost = abs(wrap(A* 首个非零航段方向 - current_yaw)) / pi
RevisitPenalty = 区域访问次数 / (1 + 区域访问次数)

U = 2.0 * Gain - 1.0 * PathCost - 0.5 * YawCost - 0.8 * RevisitPenalty
```

四项均在 [0,1]，U 本身不要求在 [0,1]。新参数均在 `config/frontier_decision_config.py`：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| min_frontier_size | 5 格 | 小前沿过滤 |
| candidates_per_cluster | 4 | 范围 3–5，安全不足时允许更少 |
| cluster_max_span | 6 m | 连通边界片段最大跨度 |
| max_clusters_per_update | 24 | 分批轮转评估，另保留当前目标所在簇（最多额外 1 簇），限制单轮 A* 数量 |
| gain_weight / path_weight / yaw_weight / revisit_weight | 2 / 1 / 0.5 / 0.8 | 评分权重，允许 0 |
| path_normalization_m | 20 m | 路程归一化尺度 |
| revisit_radius | 3 m | 区域访问记忆半径 |
| forward_cone_degrees | 30° | 当前行进方向两侧的前向优先范围 |

候选半径（默认 1.5–2.5 m）、information_radius（3 m）、camera_fov_degrees（90°）、飞行净空及预算继续复用 `config/exploration_config.py`。评分权重以 decision 配置为准。viewpoint_spacing 仍用于覆盖复查、恢复观测分区及邻近目标修复，不是候选簇拆分参数。

## 航点执行（2026-09-23 更新）

Utility 只给探索目标，使用已有 A* 安全栅格路径和 EGO 局部避障。

- 到达或确认当前航点不可达后才重新选择探索目标。地图变化、周期到达不会在飞行中反复换目标。
- 每个执行时域继续检查路径；失效时先停车，再调用原有 A* 规划到同一个航点。无安全路径才取消该目标。
- 候选评分和 A* 重算前发送位置保持并等待水平速度降至 0.05 m/s 以下，避免耗时计算期间延续旧速度指令。
- 顺序执行 A* 的第一段，不能用跨越拐角的直线替代路径。直行通过现有安全检查后执行；受阻由已有 EGO 生成并验证局部轨迹。
- 飞行段锁定航向，不传入前沿质心的观察 yaw。路径需要超过 15° 的方向调整时，先停车、检查当前机身净空再转向，然后继续飞；小幅路径方向差不反复摆头。
- 拐点采用已有控制器的减速到点方式，不按巡航速度穿越拐角。恢复自由空间时保留更小的到点误差。
- 碰撞及其他探索异常另外保存终止诊断快照，供复核当时地图和规划状态。

这次优先消除旋转前进和计算期间控制空档，会在决策和明显转弯处停车，并非全程不停飞行。深度建图、净空、刹停检查和控制器实现没有因此放宽。候选 A* 同步计算耗时仍记录在 `decision_seconds`。

一个批次没有候选不代表前沿耗尽；必须完成整轮分批评估后才累积空前沿确认。

## 运行（Windows / PowerShell）

```powershell
python run_explore.py
# 探索结束并确认返航落地后，在第二终端执行：
python navigate_target.py
```

不再提供策略切换参数。已有可用的 `planner._native_ego` 无需重编译；新环境按 [EGO 构建说明](../planner/native_ego/README.md) 编译。

报告的 `strategy` 为 `cluster_utility`，`exploration_planner` 为 `cluster_utility_astar`，航点来源为 `utility_frontier`。
`decision_config`、`decision_trace`、`selection_trace`、`arrived_frontiers` 记录参数、评分、选择与实际访问。

## 对比不同参数的运行结果

保持场景、起点、航向、传感器、飞行高度和安全参数一致，每次重新建图：

```powershell
python tools/compare_exploration_strategies.py "data/runs/<run_a>" "data/runs/<run_b>" --output "data/exploration_comparison.json"
```

脚本比较观测面积、航程、目标方向反转次数、重复到达、规划耗时和终止原因。没有完整真值面积，`full_map_coverage` 为 null；历史报告缺失字段也显示 null。

## 前向优先与验证范围

以最近行进航向（初始使用当前 yaw）为基准，选择左右各 30° 内整段直线已经验证安全的候选。优先访问次数更少、前向投影更远的候选。没有合格前向候选时按 Utility 分数换向，侧后方候选继续保留。

自动化测试覆盖前沿、候选安全、A* 绕墙代价、评分、访问记忆、标准接口、终止与航点执行。地下车库的实际覆盖率、平稳性和定位精度仍需 UE 运行验证。
