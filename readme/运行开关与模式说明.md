# 运行开关与模式说明

本文档对应当前项目代码，集中说明主程序 `run_demo.py` 使用的开关、模式、依赖关系和输出目录。修改配置文件后，Python 配置会在下次启动时直接生效；只有修改 `planner/native_ego` 下的 C++ 源码才需要重新编译。

## 当前默认运行组合

当前默认配置是：

- 使用 C++ EGO 进行去程和返航局部规划；C++ 扩展不可用时自动回退 Python EGO。
- WebSocket、UE 和 `run_demo.py` 按三个独立进程依次启动。
- 构建实时滑动局部三维占据栅格。
- 不构建、不显示、不保存全局稀疏地图。
- 返航时直接以起飞点为目标，由局部 C++ EGO 实时避障。
- 记录同步飞行状态、RGB 和深度数据到 HDF5。
- 开启 YOLO-World 检测与 SAM2 实例分割组合窗口。
- 在一个相机窗口中纵向显示 RGB、深度和 RflySim TypeID=4 真值分割图。
- 保存局部规划和返航规划的二维投影 PNG。

## WebSocket、UE 与主程序启动顺序

必须按以下顺序启动，UE 仍由用户通过 RflySim 软件手动启动。

终端 1，在项目根目录启动 WebSocket 服务并保持窗口运行：

```powershell
npm start
```

也可以使用等价命令 `node server.js`。看到
`WebSocket 服务器已启动: ws://127.0.0.1:8766` 后，再手动启动
RflySim3D/UE。等待 UE 完成 WebSocket 连接后，在终端 2 运行：

```powershell
python run_demo.py
```

`run_demo.py` 不会启动或关闭 Node.js，也不会启动 UE。它会以
`controller` 身份连接现有 WS，查询 UE 连接数；确认至少一个 UE 客户端
在线后，才读取 `config/websocket_request.json` 并原样发送。当前文件内容是：

```json
{
  "type": "set_scene_mode",
  "mode": "fixed_1"
}
```

`server.js` 会保留文件中的字段结构并立即转发给已连接的 UE 客户端。
服务端不再缓存场景命令；如果 UE 没有连接，服务端会拒绝发送，避免在错误
启动顺序下依赖补发。

要切换场景，只需修改 `config/websocket_request.json` 中的 `mode`，不需要修改 Python。文件必须是一个 JSON 对象，并包含非空的 `type`；`set_scene_mode` 请求还必须包含非空的 `mode`。发送给 UE 的场景请求保持为 `type` 和 `mode` 两个字段；WS 给 Python 的确认响应包含 `success`、`message`、`timestamp` 和实际接收端数量 `receivers`。

连接配置位于 `config/websocket_client_config.py`：

```python
host = "127.0.0.1"
port = 8766
request_file = PROJECT_ROOT / "config" / "websocket_request.json"
ue_wait_timeout = 120.0
```

如果 WS 尚未启动，`run_demo.py` 会提示先执行 `npm start`；如果 UE 在
`ue_wait_timeout` 内没有连接，程序超时退出且不会开始飞行。若提示找不到
`node`，需将 Node.js 加入 `PATH`；如果提示找不到 `ws`，在项目根目录
执行一次 `npm install`。

## 每次运行的数据目录

主程序每启动一次，就会创建一个独立目录：

运行目录生成逻辑位于 `config/run_output.py`，主程序在 `application/demo_runtime.py` 中把各保存模块的输出路径统一重定向到该目录。

```text
data/
└── runs/
    └── run_YYYYMMDD_HHMMSS_ffffff/
        ├── recordings/
        │   └── flight_rgbd_*.h5
        ├── planning/
        │   ├── local_*.png
        │   └── return_local_*.png
        ├── detections/
        │   ├── yolo_world_detection.mp4
        │   └── sam2_segmentation.mp4
        └── maps/
            ├── semantic_instances.json
            ├── garage_global_sparse_map_*.h5
            └── garage_global_sparse_map_*_foxglove.mcap
```

控制台启动时会输出：

```text
本次运行数据目录：.../data/runs/run_...
```

注意：

- YOLO-World/SAM2 默认同时保存检测视频、分割视频和本次飞行的语义实例地图。
- 局部三维占据栅格只供实时规划使用，不单独保存；保存的是它的二维规划投影。
- 旧版本已经生成的 `data/recordings`、`data/maps` 和 `Visual/时间戳` 文件不会被自动移动或删除。
- 即使某项保存功能关闭，本次运行的根目录仍会保留，便于区分运行批次。

## 局部规划模式

配置文件：`config/planner_config.py`

`navigation_mode` 控制正常任务航段，`return_navigation_mode` 控制返航航段。两者支持相同的四种值：

| 值 | 作用 | 是否使用局部地图 |
|---|---|---|
| `ego_native` | C++ EGO 三维 B 样条规划；原生模块异常时自动回退 Python EGO | 是 |
| `ego` | 纯 Python EGO 三维 B 样条规划 | 是 |
| `astar` | 二维占据栅格 A* 局部规划 | 是 |
| `depth_guard` | 不执行地图路径搜索，只保留前向深度急停保护 | 仅使用深度安全信息 |

当前默认值：

```python
navigation_mode = "ego_native"
return_navigation_mode = "ego_native"
```

相关布尔开关：

| 开关 | 默认值 | 说明 |
|---|---:|---|
| `unknown_is_occupied` | `False` | `True` 时把未观测体素视为障碍，安全性更保守，但初期更容易无路可走 |
| `allow_diagonal` | `True` | 二维 A* 是否允许斜向邻接；不影响 EGO 内部三维搜索 |

模式依赖：`OccupancyGridConfig.enabled=False` 时不会创建局部规划器，因此 `ego_native`、`ego` 和 `astar` 都无法执行地图避障。

## 局部地图开关

配置文件：`config/occupancy_grid_config.py`

| 开关 | 默认值 | 说明 |
|---|---:|---|
| `enabled` | `True` | 构建随无人机移动的局部三维占据栅格，是 EGO 和 A* 的实时障碍来源 |
| `depth_is_range` | `False` | `False` 表示输入深度是相机 Z 轴深度；`True` 表示射线距离 |

项目没有局部 3D 占据地图显示窗口；该功能已经移除。局部地图仍然存在并参与规划。

## 全局地图与返航模式

配置文件：`config/global_map_config.py`

| 开关 | 默认值 | 生效条件与作用 |
|---|---:|---|
| `enabled` | `False` | 全局总开关；关闭后不建图、不回环、不显示、不保存，并采用局部规划器直返起飞点 |
| `depth_is_range` | `False` | 与局部地图相同，选择深度值含义 |
| `loop_closure_enabled` | `True` | 仅 `enabled=True` 时生效，执行关键帧点云回环校正 |
| `visualize` | `True` | 仅 `enabled=True` 时生效，打开全局稀疏地图 Open3D 窗口 |
| `show_free_voxels` | `False` | 全局窗口是否同时显示空闲体素 |
| `save_on_close` | `True` | 仅有成功地图更新时，在关闭阶段保存全局地图 HDF5 |
| `export_foxglove_mcap_on_close` | `True` | 依赖 `save_on_close=True`，额外导出 Foxglove MCAP |

返航数据流：

```text
enabled=False:
起飞点目标 → return_navigation_mode 对应的局部规划器 → 实时避障直返

enabled=True:
全局地图 A* → 多个稳定返航航点 → 局部返航规划器逐段实时避障
                     └─ A* 无路时沿真实去程轨迹反向返航
```

恢复全局地图模式只需修改：

```python
enabled: bool = True
```

不需要重新编译 C++。

## 飞行任务开关

配置文件：`config/mission_config.py`

| 开关 | 默认值 | 说明 |
|---|---:|---|
| `return_to_origin` | `True` | 完成全部任务航点后是否返航 |
| `face_path` | `True` | `True` 时正常航段机头朝向飞行方向；`False` 时保持指定 yaw |
| `restore_initial_yaw` | `True` | 返航到起飞点后恢复本次解锁前记录的实测航向，稳定后再悬停、降落；不使用配置的 `initial_yaw` 作为返航朝向 |

任务目标由 `waypoints` 配置。每个 `MissionWaypoint` 包含：

- `position_ned`：目标 NED 坐标。
- `yaw`：该航点指定航向。
- `hold_time`：到达后悬停时间。

## 飞行控制开关

配置文件：`config/drone_config.py`

| 开关 | 默认值 | 说明 |
|---|---:|---|
| `reset_initial_pose` | `False` | 连接时是否强制重设水平位置和航向；PX4 EKF 已初始化后不建议开启 |

`initial_xy_yaw` 只在 `reset_initial_pose=True` 时生效。其余 `guided_*` 字段是速度、加速度、yaw 和到达容差参数，不属于模式开关。

当前为提高实时检测稳定性采用较慢速度：`guided_max_forward_speed=0.75 m/s`、`guided_max_horizontal_acceleration=0.30 m/s²`；EGO/局部规划的实际直线巡航上限为 `cruise_max_speed=0.60 m/s`，避障上限为 `avoidance_max_speed=0.35 m/s`。实际速度取飞控上限和规划器限速中的较小值。

## RGB-D 相机显示模式

配置文件：`config/camera_config.py`

| 开关或模式 | 默认值 | 可选值与说明 |
|---|---:|---|
| `show_rgb` | `False` | 是否显示实时 RGB 窗口 |
| `show_depth` | `False` | 是否显示实时深度窗口 |
| `show_segmentation` | `False` | `False`：不向 UE 请求 TypeID=4；`True`：请求并显示真值分割图，重启视觉接口后生效 |
| `depth_display_mode` | `grayscale` | `grayscale`：黑白深度；`color`：彩色伪彩色深度 |
| `suppress_sdk_output` | `True` | 是否隐藏 VisionCaptureApi 启动时的普通提示 |

当对应开关打开时，三个画面会缩放到 480 像素宽，并按 RGB、深度、TypeID=4 的顺序纵向组合在同一个 OpenCV 窗口中。当前三个开关默认均关闭，只显示纵向组合的 YOLO-World 与 SAM2 窗口，便于观察模型 FPS。预览线程直接复用主 RGB-D 数据流已缓存的最新帧，不会为显示窗口再向 SDK 重复取帧。TypeID=4 只用于仿真真值预览；关闭 `show_segmentation` 时不向 UE 请求它，不会影响 RGB-D 建图、EGO 或语义导航。

相机本身没有 `enabled` 总开关，因为同步观测、建图、记录和实时感知都依赖相机输入。

传感器定义文件：`config/sensors/VisionSensors_RGBD_Config_v0.json`

- `TypeID=1`：RGB 相机。
- `TypeID=2`：深度相机。
- `TypeID=4`：由 UE `CustomDepthStencilValue` 渲染的真值分割图。
- `TargetCopter` 必须与 `Config.copter_id` 一致。
- `DataCheckFreq` 是传感器输出频率。
- `EularOrQuat=0` 表示使用欧拉角安装姿态字段。

TypeID=4 不会自行识别或标注类别。本项目只读取和显示 UE 场景已经写入的 `CustomDepthStencilValue`，不再在 Python 启动阶段修改 Actor/Mesh 标注。完整类别表、UE 操作步骤、全场景覆盖要求和验收规范见 [`RflySim_UE场景语义标注规范_TypeID4.md`](RflySim_UE场景语义标注规范_TypeID4.md)。

## YOLO-World 与 SAM2 实时感知开关

配置文件：`detections/object_detect.py` 中的 `DetectorConfig`

| 开关或模式 | 默认值 | 说明 |
|---|---:|---|
| `enabled` | `True` | 是否同时加载 YOLO-World 与 SAM2 并显示组合窗口 |
| `device` | `0` | 使用第 0 块 CUDA GPU；可改为 `cpu` 使用 CPU |
| `use_fp16` | `True` | CUDA 上使用 FP16 推理；`cpu`/MPS 自动保持默认精度 |
| `confidence` | `0.12` | YOLO-World 最低检测置信度；较低阈值用于提高车库柱子召回率 |
| `max_detections` | `30` | YOLO 单帧最多保留的候选框数，防止低阈值场景候选爆发 |
| `max_sam_prompts` | `12` | SAM2 单帧检测框预算；柱子与车辆轮流分配，余量给其他类别 |
| `inference_fps` | `30.0` | 感知线程的目标上限，实际 FPS 仍受两模型耗时限制 |
| `class_prompts` | 地面、墙、天花板、柱、标牌、消防箱、车、人和停车道闸英文提示词 | 标牌使用墙面指示牌、方向牌、出口标志等同义词，统一为 `signboard`；消防箱同义词统一为 `fire cabinet`。`traffic cone` 和 `light` 已移除 |
| `sam_weights` | `detections/Yolomode/sam2.1_t.pt` | 项目内的 SAM2.1 Tiny 权重，使用基于源码目录构造的绝对路径，不受启动目录影响 |
| `window_name` | `YOLO-World Detection / SAM2 Segmentation` | 纵向组合窗口标题 |
| `hidden_box_classes` | `floor, ceiling, wall` | 仅隐藏这些类别的 YOLO 预览框；不影响检测、SAM2 分割和下游数据 |
| `semantic_landmark_classes` | `column, car, truck, bus, van` | 写入本次三维语义地图并关联实例ID的类别 |
| `instance_mahalanobis_gate` | `7.815` | 三维创新马氏距离平方门限，对应3自由度95%卡方范围 |
| `instance_kalman_process_noise_std` | `0.05` | 静态柱子NED卡尔曼预测的过程噪声标准差，单位 m/√s |
| `instance_mask_pixel_noise_std` | `3.0` | SAM2掩膜代表点的像素标准差，用于反投影雅可比误差传播 |
| `instance_depth_noise_std` | `0.60` | 近距离光轴深度测量标准差基准，单位 m |
| `instance_duplicate_merge_distance_xy` | `1.5` | 柱子等静态地标的NED水平合并距离，单位 m；不用于车辆 |
| `column_min_vertical_extent` | `1.5` | JSON 保存时柱子沿 NED Z 轴必须达到的最小垂直范围，单位 m |
| `column_min_vertical_aspect_ratio` | `1.2` | JSON 保存时柱子垂直范围相对最大水平范围的最小比例 |
| `instance_depth_min/max` | `0.3 / 15.0` | 生成实例三维位置时接受的掩膜深度范围，单位 m |
| `instance_depth_stride` | `4` | 掩膜内深度采样步长，避免三维定位拖慢实时推理 |
| `instance_depth_min_points` | `12` | 建立三维实例位置所需的最少有效深度采样点 |
| `semantic_map_path` | 当前 `run_.../maps/semantic_instances.json` | 本次飞行构建并保存的 NED 语义地图文件 |
| `semantic_map_min_observations` | `3` | 实例至少累计匹配多少次后才写入持久地图，过滤瞬时误检 |
| `instance_display_min_observations` | `10` | 柱子和车辆累计多少次有效观测后才在 SAM2 窗口显示实例ID |
| `vehicle_max_association_distance` | `2.5` | 车辆观测与预测位置允许的最大三维距离，单位 m |
| `vehicle_appearance_gate` | `0.55` | 掩膜颜色直方图的 Hellinger 距离上限，越小越严格 |
| `vehicle_viewpoint_noise_std` | `0.45` | 车辆可见表面中心随视角改变的额外测量标准差，单位 m；初始化、关联和更新均使用 `R_eff=R+σ²I3` |
| `vehicle_confirmation_observations` | `3` | 新车辆至少匹配3个不同时间戳的有效观测才分配正式ID；待确认目标超过2秒未匹配则丢弃，不占正式编号 |
| `vehicle_ambiguity_margin` | `0.12` | 车辆关联候选代价差不足此值时暂不分配身份 |
| `save_semantic_map` | `True` | 正常关闭感知线程时原子写回语义地图 |
| `show_instance_ids` | `True` | 在 SAM2 掩膜中心显示 `column_01`、`vehicle_01` 等ID，不显示车辆颜色文字；掩膜显示色仍按身份固定 |
| `save_videos` | `True` | 是否分别保存 YOLO-World 检测视频和 SAM2 分割视频 |
| `video_fps` | `15.0` | 输出 MP4 的固定帧率；根据真实经过时间抽帧或补帧 |
| `video_codec` | `mp4v` | OpenCV MP4 编码器 FourCC |

检测权重为 `detections/Yolomode/yolov8s-worldv2.pt`，分割权重为 `detections/Yolomode/sam2.1_t.pt`。YOLO-World 检测框作为 SAM2 的逐帧提示；没有框时跳过分割。柱子同义提示统一为 `column` 并按类别去重；车辆还会去除跨车型的高度重合重复框。柱子和车辆均从掩膜内采样同步深度，通过相机内参、同步 `T_world_camera` 转换成 NED 点云和协方差。

柱子继续使用静态卡尔曼滤波、马氏关联、`1.5 m` 近邻合并和垂直几何过滤。定位失败显示 `column [unmapped]`，未达到10次有效观测显示 `column [confirming]`；确认后按确认顺序分配 `column_01` 等视频编号。车辆的处理见下段。

每次运行从空语义地图开始，正常关闭时写入 `data/runs/run_.../maps/semantic_instances.json`，下次不加载。组合窗口上栏显示检测框，下栏显示半透明掩膜及柱子/车辆ID。两路视频由独立队列写入 `data/runs/run_.../detections/`。算法说明见 [`NED卡尔曼语义实例关联说明.md`](NED卡尔曼语义实例关联说明.md)。

本场景车辆与柱子均静止。车辆通过 SAM2 掩膜和同步 RGB-D/NED 位姿定位，使用三维静态位置卡尔曼滤波、掩膜颜色外观和一对一全局分配关联；不估计车速，离开视野后保留原位置，过程噪声共用 `instance_kalman_process_noise_std`。车型之间高度重合的重复检测框会被去除。车辆不执行柱子的 `1.5 m` 距离合并；两个候选难以区分时暂不显示ID，历史状态保持不变。默认累计10次有效观测后显示 `vehicle_01` 等ID，颜色跟随身份。该身份跨 `car/van/truck/bus` 标签波动保持一致，地图 `class_name` 保留首次关联的规范车型；车辆标记为 `is_static=true, is_obstacle=true`。原显示开关已重命名为 `show_instance_ids`。

文件顶层的 `instance_count` 是过滤后的 `instances` 实际数量。柱子的 `instance_id` 仍按类别连续编号，`runtime_instance_id` 用于合并追溯，`video_instance_id` 是视频确认编号。车辆三个ID使用同一 `vehicle_NN` 命名空间，不因过滤或导出而重新编号（允许缺号）；尚未达到视频确认条件时 `video_instance_id` 为 `null`。`position_world` 和 `bbox_3d` 使用 NED 世界坐标，车辆包围盒随最新位置更新。`last_seen` 表示最后有效观测时间，并不代表该车当前仍可见。记录字段布局仍为版本5，每次运行重新建图；下面是保留的柱子记录示例。

```json
{
  "instance_id": "column_01",
  "runtime_instance_id": "column_03",
  "video_instance_id": "column_01",
  "class_name": "column",
  "aliases": [
    "concrete column",
    "concrete pillar",
    "parking garage pillar",
    "support column",
    "support pillar",
```

## 飞行数据记录与压缩模式

配置文件：`config/recording_config.py`

| 开关或模式 | 默认值 | 可选值与说明 |
|---|---:|---|
| `enabled` | `True` | 是否记录同步飞行状态、RGB 和深度到 HDF5 |
| `hdf5_compression` | `lzf` | `lzf`：快速压缩；`gzip`：体积更小但更耗 CPU；`none`：不压缩 |
| `hdf5_compression_level` | `4` | 仅 `gzip` 模式生效，范围 0～9 |

## 二维规划图保存开关

配置文件：`Visual/astar_2d_visualizer.py` 中的 `AStarVisualizationConfig`

| 开关 | 默认值 | 说明 |
|---|---:|---|
| `enabled` | `True` | 是否异步保存局部规划、返航规划和全局返航二维投影 PNG |

`local_save_interval` 控制局部图保存间隔。该模块只保存图片，不再打开局部 3D 地图窗口。

## 强化学习回合重置模式

文件：`rl_episode_reset.py`

`RLEpisodeResetter` 是独立的仿真专用工具，不会被 `run_demo.py` 自动调用。只有显式调用 `reset(vehicle)` 才会强制中止当前仿真飞行、重启对应 CopterSim 实例并重置位置。不要用于真实飞行器。

## 常用组合

### 当前模式：无全局地图的局部 EGO

```python
GlobalSparseMapConfig.enabled = False
OccupancyGridConfig.enabled = True
PlannerConfig.navigation_mode = "ego_native"
PlannerConfig.return_navigation_mode = "ego_native"
```

### 启用全局地图和全局返航

```python
GlobalSparseMapConfig.enabled = True
GlobalSparseMapConfig.save_on_close = True
GlobalSparseMapConfig.export_foxglove_mcap_on_close = True
PlannerConfig.return_navigation_mode = "ego_native"
```

### 只显示 YOLO-World 与 SAM2 窗口

```python
CameraConfig.show_rgb = False
CameraConfig.show_depth = False
CameraConfig.show_segmentation = False
DetectorConfig.enabled = True
GlobalSparseMapConfig.visualize = False
```

如仍需保存二维规划图，请保持 `AStarVisualizationConfig.enabled=True`；它不会打开窗口。

### 只飞行、不记录 HDF5

```python
RecordingConfig.enabled = False
```

这不会关闭局部建图、EGO、RGB-D 数据流或飞行记录。
