# 探索启动配置

在项目目录运行以下任一命令：

```powershell
python run_explore.py          # 默认 SAM3
python run_explore.py --sam3   # 显式使用 SAM3
python run_explore.py --sam2   # YOLO-World + SAM2
python run_explore.py --fastlio  # 默认 SAM3，同时启用 FAST-LIO 实验建图
python run_explore.py --sam2 --fastlio
```

SAM3 使用 `detections/Yolomode/sam3.pt`，启动探索时自动启动本地服务并等待预热；退出时关闭本次启动的服务。已运行的兼容服务会被复用，不会由本次进程关闭。SAM2 使用现有 YOLO-World 与 SAM2 权重。

探索规划参数沿用 GitHub v3 的命令行选项，例如 `--timeout`、`--max-radius`，完整列表可用 `python run_explore.py --help` 查看。探索入口不读取 `config/explore.json`；该 JSON 仍供独立目标导航使用。

启用 `--fastlio` 后，起飞前需静止等待 FAST-LIO 初始化。结果位于本次运行目录的 `fastlio/map.html`、`fastlio/semantic_map.json`、`fastlio/inputs.h5` 和 `fastlio/capture_report.json`。这是独立实验地图，语义 ID 与探索地图不共用；`exploration/map.html` 和导航仍使用 PX4/雷达与回环校正。当前扫描标记为 `snapshot_assumed`，尚未验证是否逐点扫描；不代表真实同步或精度已经通过验证。运行结束后可用 `python tools/audit_fastlio_inputs.py "data/runs/实际运行目录"` 检查采集质量。

原始录制、FAST-LIO 求解和网页发布分别执行。`capture_report.json` 中 `completed` 反映原始数据是否完整，`shadow_completed`、`shadow_overflow` 和 `shadow_skipped_scans` 用于检查在线求解；`semantic_map.json` 中的 `synchronization` 可检查语义时间匹配。求解跟不上时保留原始记录，使用离线回放重新计算；原始采集本身溢出时报告会标记失败。

`shadow_reordered_imu` 记录求解器在尚未处理的 IMU 队列中纠正的小幅接收乱序次数；原始文件始终保留实际接收顺序。超过 50 毫秒、重复或已经参与求解的时间戳异常仍会停止在线求解并写入报告，需要检查原始数据。
