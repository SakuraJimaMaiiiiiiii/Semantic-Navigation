# RflySim 激光雷达默认接入

参考本机 demo：
`D:\PX4PSP\RflySimAPIs\8.RflySimVision\0.ApiExps\1-UsageAPI\3.PointCloudAPI\2.LidarAPIPointCloudDemo`。
已阅读 Python 共享内存/UDP 例程、两份配置、Readme.pdf，以及本机 SDK 的点云解码路径。

## Demo 的实际功能

`jsonLoad → sendReqToUE4 → startImgCap → vis.Img[index] → Open3DShow`。
例程是点云接收与显示，不包含占据建图、A* 或飞行避障。
实际 Config.json 使用 TypeID=20，900×32 采样配置、10 Hz 检查频率，水平 -45°～45°、
垂直 -20°～20°，量程 200 m，安装偏移 [0,0,-0.3] m。
Readme.pdf 中部分段落写 TypeID=22，与实际配置不一致；这里以实际配置和安装 SDK 为准。
共享内存模式用于 Windows；UDP 点云也有独立例程。

本机 SDK 把 int16 XYZ 按最大量程/32767 解码为米，返回 Nx4 数组。
第四列在当前零通道配置下填 0，开启额外通道后是 stencil 原始值，不是距离。
`ImgData` 包含 CopterID、axis_type、6 个位置/角度值和点数；接入只接受目标飞机的 axis_type=0 机体点云；本机采样验证需按 FLU 转为 FRD（Y、Z 取反）。

## 已接入的结构

```text
统一 VisionCaptureApi 管理器
  ├─ RGB-D → 原有语义识别、深度建图与前向深度急停
  └─ Type20 LiDAR → 时间戳匹配 PX4 位姿 → FRD 转 NED
                  → 径向射线融合 → 原有局部/全局占据地图
                                                ↓
                                 Utility → A* → EGO → 控制器
```

启用时只发送一组 RGB-D + LiDAR 请求，不另开飞控连接、不启动 demo 的 BAT。
这样可以避免项目启动时 `RflyClearCapture` 清掉另一个进程申请的雷达，以及 SeqID 冲突。

雷达当前配置在 `config/lidar_config.py`：SeqID=3、TypeID=20、360° 水平扫描、
32 层采样、30 m 量程、共享内存。第一次接入采用机体中心零安装变换，
避免混淆“相对传感器”与“相对机体”坐标；修改安装偏移需要同步验证坐标变换。
剔除 0.6 m 内近机体回波、非有限回波、最大量程边缘回波；最多选取 3000 点、按 5 Hz 融合。
无效/未返回射线不会被猜测成空闲，也不会在最大量程上制造假墙。
每个地图仍按自己的融合距离截断远端射线，截断端不标为障碍。

点云与 RGB-D 共用时钟偏移，并使用已有状态历史插值匹配点云时刻；
同步误差超过相机配置允许值时丢弃点云帧，不用当前位姿硬套旧点云。

### 动态定位与时间配对修正（2026-10-07）

- 三维反投影以深度曝光时间为准，RGB 时间只参与 RGB/深度偏差检查，不再取两者的平均时间作为几何时刻。
- MAVLink 位姿从完整的 `ATTITUDE`、`LOCAL_POSITION_NED` 消息快照读取，使用姿态消息的主机接收时间。四元数由同一条姿态消息计算，避免将仍然非零但已经过期的 `ATTITUDE_QUATERNION` 与当前时间组合。直接 SDK/UDP 模式仍读取 SDK 状态数组。
- 姿态与位置消息的源时间差记录在 `DroneState.pose_sync_error`，超过已有 `max_state_sync_error` 的样本不进入同步历史。不向前外推旧位置来伪造同步测量。
- 插值误差包含一半的相邻位姿时间跨度；不能因为距离其中一端很近，就跨过很长的遥测缺口。旋转使用最短弧 SLERP，且不修改历史四元数数组。
- 为图像匹配雷达的步骤提前到 YOLO 推理前，防止慢推理淘汰对应雷达历史。雷达采集仍落后于图像时，感知线程最多等待 `2 × camera_max_skew`（默认 100 ms），再选最近帧；接受门槛仍为 50 ms，地图积分与控制线程不参与等待。
- 几何协方差使用实际同步误差和 RGB/深度时间差更新时间不确定性，避免运动中继续声称固定的较小时间误差。

运行结束的 `lidar_camera_alignment.json` 新增 `pose_timeout_frames`、`pose_rejected_frames`、`last_pose_sync_error_seconds`。分别用于检查雷达等待位姿超时、位姿插值超限及最后一次插值误差。原有 `matched_frames / unmatched_frames / rejected_frames` 仍用于检查雷达与相机的时间匹配和投影一致性。

旧录制 `run_20261005_150059_470760` 中有 238 次时间匹配、846 次未匹配；保存的一帧投影深度残差中位数约 1 mm。这只能说明该帧部分对应点的深度相符，不能代表世界坐标达到毫米精度。录制还存在图像时间领先主机接收时间的情况，旧地图不作自动校正，应重启采集新地图后比较。

这些修改改善的是数据时间一致性，不等于完成了雷达惯性里程计或外参自动标定。PX4 位置估计误差、传输固定延迟及遮挡仍可能影响绝对定位；本轮只有离线回归测试，尚未进行 UE 飞行精度验证。无需重新编译 C++。

雷达不覆盖前向深度急停值，也不修改相机内参、语义 mask 或深度对齐。
起飞前仍需成功融合首帧；规划器不再单独轮询雷达失活状态，沿用融合地图与轨迹检查。
运行时关闭仅保存深度关键帧的回环重建，避免重建丢失雷达占据证据。

## Windows 运行

启动原来的 UE/RflySim 场景及 WebSocket 服务，再运行：

```powershell
python run_explore.py
```

雷达与视觉在所有 DemoRuntime 任务中一起启动，随会话关闭，不再提供雷达开关。已有 EGO 扩展无需重新编译。
本次运行使用的合并配置保存在 `data/runs/<run>/sensors_rgbd_lidar.json`。
启动成功应打印 `LiDAR enabled: Type20 / 360° / body FRD ...`，退出打印已融合雷达帧数。

`exploration/map.html` 展示融合地图在飞行高度附近的切片。没有新增独立 Open3D 点云窗口。
三维地图仍保留天花板和地面，规划切片继续按机身高度带判断，不能简单删除它们。

## 文件与验证范围

- `sensors/rfly_lidar.py`：复用 SDK 接收端、点云检查与过滤。
- `mapping/lidar_mapping_worker.py`：时间同步、坐标转换、双地图融合线程。
- `mapping/local_occupancy_grid.py` / `global_sparse_occupancy_map.py`：增加雷达射线入口。
- `application/demo_runtime.py`：统一传感器配置和生命周期。
- `run_explore.py`：无需雷达参数。

自动化测试覆盖坐标旋转、XYZ 米制读取、无效回波、后方点云、射线清空、量程截断和失活检测。
尚未与正在运行的 UE 场景联调，不能宣称真实点云、位姿同步或避障效果已经通过仿真验证。
首次运行应核对已知墙面/柱子在融合地图的位置；若出现整体偏移或重影，应先检查时间与坐标标定。

## 雷达与语义相机对齐

雷达点按采集时刻机体位姿转世界坐标，再按图像时刻相机外参转光学坐标，使用内参投影到像素。
比较光轴 Z 深度，不把径向距离当作图像深度。相机安装偏移参与变换，安装角由度转换为弧度。

`config/lidar_config.py` 配置：匹配时差最多 50 ms，一致性阈值 0.3 m + 深度的 2%。
掩膜内部至少 6 个一致点才参与物体点云融合；排除边缘和不一致回波。
不满足要求时保留原深度定位，不降低原定位协方差。融合的是可见物体表面点，
不保证恢复被遮挡物体的真实中心，未实现逐激光束扫描去畸变。

运行目录 `lidar_camera_alignment.png` 保存首个有投影点的叠加图：绿色一致、橙色拒绝。
退出时 `lidar_camera_alignment.json` 保存匹配/拒绝帧数、最后一次误差和融合物体次数与雷达点数。
没有匹配时可能不生成预览图；unmatched_frames 可用于排查时序。
尚需实际场景标定和精度验证。

## 导航、避障和返航的覆盖范围

雷达融合位于公共局部/全局占据地图层，由公共地图层提供：普通航点导航、
语义目标导航、探索和返航的 A* / EGO 均读取这两张融合地图。
全局地图可视化和地图导出也读取融合后的体素；原始 RGB-D 录像/记录仍保留原测量。
普通局部规划、缓存轨迹、语义导航和返航不再通过地图回调单独检查雷达失活。
因此雷达停止更新但深度仍正常建图时，不会仅因雷达超时中止任务；原地图新鲜度和轨迹安全检查保留。
两传感器乱序到达时，旧帧按采集位姿融合，但不会回退地图时间和当前地图中心。

这里的雷达参与是时间/空间对齐后的几何融合，不是全图自动外参标定。
语义点云融合仍仅限掩膜内经过一致性验证的对应点；不把稀疏雷达点外推到整个深度图。
原始相机前向深度急停继续独立保留。仅深度保护模式 depth_guard 不等价于三维点云避障；
正常导航继续使用默认 ego_native 模式。

## 参考预处理项目的融合调整（2026-09-28）

参考 `E:\files\code\proprecessing_data\proprecessing_data` 中
`fuse_linghou_camera_lidar.py::main`、`src/camera_lidar_transform.py` 和
`src/multimodal_registration.py` 的时间配对、外参变换与点云拼接方式。
该项目按最近时间戳配对，在 base_link (FLU) 合并两个点云，并保留 source=0/1，
并非在线 ICP 标定或用雷达残差整体修正深度图。

本项目使用 FRD/NED，继续使用 UE 相机安装参数，不复制参考设备的 URDF、flip_xy 或畸变参数。
雷达世界点按图像时刻的相机位姿转换为光学点；与掩膜关联后，将其真实 XYZ
与相机反投影点拼接，再变换到 NED 求中位位置及百分位包围盒。
`sensors/lidar_camera_alignment.py::fuse_camera_lidar_points` 返回独立的合并点云；
雷达点数直接按本次有效雷达输入统计，不再为计数创建来源数组。
删除原 mask_depth_correction，避免把稀疏雷达残差平移到整个相机物体表面。
`semantic_fused_objects`、`semantic_lidar_points` 替代旧 semantic_depth_corrections 统计。

局部/全局占据建图继续融合两路射线，不使用相机起点对雷达点清空射线，也不重复计入一帧配对点。
相机和雷达独立建图可覆盖各自视野；语义配对只使用时差满足条件的对应帧。
此方法保留两路真实测量，不保证消除系统标定误差；密集相机点也可能主导中位位置。
没有引入参考项目的离线 PCD 读取/绘图依赖，未改变 A*、EGO 或控制器。
