# 最终地图的车辆与柱子连续编号

探索期间使用稳定跟踪 ID，过滤碎片、合并重复实例后可能留下空号。
此时不重排 ID，否则同一辆车会在飞行中换号，历史记录中的目标也可能指向另一辆车。

本次在正常完成探索、停止录制后，对最终地图分别编号：

- 车辆：`vehicle_01`、`vehicle_02`……
- 柱子：`column_01`、`column_02`……

`mapping/semantic_numbering.py` 提供共同的编号函数。
普通探索通过 `SceneMemory.number_final_instances()` 同步更新记录、体素标签、
观察地点关系和共同观察关系，再保存语义图和导航缓存。
回环地图在 `LiveLoopMapping.finalize()` 强制发布最终版本时使用同一规则，
即使最后一次实时更新后没有新增关键帧，也执行最终编号。

最终 HTML 使用最终记录，因此与对应语义图、占据标签及目标导航 ID 一致。
实时探索和已经录制的视频仍使用原始稳定 ID，不能回写历史画面。
`instance_id_mapping.json` 保存旧到新编号；最终记录保留源实例、合并和视频编号，
回环版本另外保留 `source_identity_mapping.json` 的原始识别关联证据。
旧编号不作为最终命名空间内的别名，避免旧 `vehicle_02` 错指向新的 `vehicle_02`。

正常重新运行 `python run_explore.py` 即可，无需 CMake。
本次不会重写已有实验数据；异常中断的诊断文件保留当时的跟踪编号。
