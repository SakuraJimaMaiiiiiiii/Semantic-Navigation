# 位置参考与耗时规划解耦

针对 run_20261028_140435_896686 中直线飞行仍反复加减速、点头的现象，本轮把路径求解移出位置参考更新循环。未修改 PX4 PID、电机时间常数、最大速度或现有加速度参数。

## 运行方式

继续使用原来的启动命令。探索、物体导航和返航只要通过 `move_waypoint_guided` 执行，都会自动使用这条异步规划链路，无需新参数或 CMake 重编译。

- 飞行控制线程持续运行位置参考的加速度/加加速度限制、航向限速、暂停恢复和 SDK 设定值更新。
- 每个飞行接口只有一个 WaypointPlanning 工作线程。线程持有规划器计算权，按照已有 replan_rate 消费最新的位置、速度和目标；不会积压每个控制周期的请求。
- 后台只计算和发布结果，不发送飞行指令。地图读取、投影、A* 和 EGO 求解不会让飞行控制线程等待它们完成。
- 首次尚无可执行结果时保持；已有当前航段/曲线仍有效时继续执行。滚动航点交接保留上一份完成的结果，避免每次交接都清零位置参考；不会接受旧请求迟到的结果，也不会在旧目标已位于新方向后方时向后拉回。
- EGO 跟随目标按机体在已发布曲线上的位置前移，不需要下一次求解才能更新前视点。

## 执行约束与数据交接

每份已发布结果包含匹配的路径、认证网格、回环版本及诊断上下文；路径数组复制为只读，避免后台下一次计算修改正在执行的路径。

局部地图在融合完成后发布只读 `execution_snapshot`。高频执行复核只读取已完成的快照，不等待融合写锁，也不构造整张地图。对当前指令段检查完整净空体积：新占据格和已观测但不确定的格会使其暂停；从未观测的格只能沿用此前网格已认证的历史自由证据，不会被直接填成自由格。回环导航版本改变时，旧结果失效。

悬停、降落会作废待完成请求；任务结束和运行时关闭会先停止规划线程，再关闭其依赖的地图和传感器。后台错误会返回飞行线程；碰撞检查仍在飞行线程执行。

`local_planning_seconds` 现在记录最近一次采用的后台计算时长；`planning_seconds` 是当前控制循环内轮询、健康检查和复核等耗时。由于两者并行，不能再按同步流程将前者与复核时间相加解释后者。

## 主要代码

- 新增 `planner/waypoint_planning_worker.py`。
- `vehicle/rfly_multirotor.py`：持续参考更新、异步结果采用、生命周期取消与关闭。
- `navigation/mission.py`：分离 compute_plan 与飞行线程的健康/执行通知，使用匹配的认证结果复核。
- `navigation/route.py`：当前短航段的局部体积复核。
- `mapping/local_occupancy_grid.py`：完成后发布执行用快照。
- `planner/local_avoidance_planner.py`：普通局部规划结果的轻量执行复核。
- `application/demo_runtime.py`：依赖关闭顺序。

## 验证

Windows 项目环境完整回归 154 项通过。新增测试验证：求解被阻塞时参考仍更新且只有飞行线程更新 SDK 设定值；取消/目标变化后旧计算不被发布；后台错误上报；曲线前视点推进；新障碍/观测不确定格拒绝旧航段；滚动交接保留有效结果；回环版本变化拒绝旧结果。

受控测试中，1.5 秒内产生 25 次位置指令，其中 16 次为前移参考；后台求解持续阻塞时，指令间隔中位数 0.062 秒，95 分位 0.063 秒。该测试没有连接 UE、模型推理或真实飞控，只证明求解等待不再直接卡住参考更新；配置目标仍为 20 Hz，Windows 调度下实际频率可能低于目标。

已有恢复计时测试使用即时发布的测试桩隔离虚拟时钟计算，真实线程行为由新增阻塞求解测试独立覆盖，运行时代码没有同步兜底分支。
