## 执行延迟

上述七个无移动失败点，最后一次规划总耗时为 2.797–3.687 秒，其中规划后复核为 1.546–2.890 秒。规划结果本身已经允许 route_clear，所以这批快照不能归因于 EGO 没有找到路。

最后发送的位置参考相比快照中的机体位置，水平前伸量仅约 0.9–9.4 cm：W2=1.26 cm、W4=1.82 cm、W6=1.17 cm、W8=8.38 cm、W9=9.45 cm、W10=0.91 cm、W11=1.62 cm。这是末次命令证据，不是整段平均速度。

当前无移动判定为 8 秒内没有达到 0.15 m 的进展。多秒一次的有效命令、很小的参考前伸量和较保守的参考加速度共同解释了“路径畅通但被判无移动”。还需修复控制与阻塞性地图复核耦合，不能只提高 no-motion 超时掩盖问题。

## 转向时序

align_yaw 中每轮先调用 health_check，然后以固定 period（默认 0.05 秒）积分 command_yaw。健康检查一旦耗时很长，实际发送间隔变长，而航向参考仍只前进 0.05 秒的量；可造成参考转向速率远低于配置值，最后 30 秒超时。此为当前代码中已确认的时间积分问题。快照没有逐次转向耗时序列，因此不能给出每个点完整的航向响应曲线。

## 结论与下一步

本次七个无移动点的局部航段在失败快照中都畅通，三个点失败于转向超时。HTML 使用 blocked 统一标记执行失败，因此名称容易被误读为障碍堵塞。

应优先分离高频位置/航向设定点更新与耗时规划复核，修正 yaw 的实际时间积分，并使地图健康读取不被融合写锁长时间阻塞。同时在 HTML 区分执行停滞、转向超时与真实路径拒绝。无需继续统一缩小障碍距离。
