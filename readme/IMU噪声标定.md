## 采集专用静止数据

启动 UE 和 CopterSim/PX4，保持飞机在地面、未解锁、场景不移动。关闭 `run_explore.py`、其他占用同一架飞机控制接收端口的 Python 程序。工具只请求遥测，不执行解锁、Offboard、起飞、降落或重置。

在项目 Python 环境运行：

```powershell
python tools/record_stationary_imu.py --seconds 1800
```

默认本机 1 号机，采用 SDK SIL 端口约定：发送 20100、接收 20101；可通过 `--host` 和 `--copter-id` 指定。不是串口/实机采集入口。工具依赖现有 pymavlink/numpy，不依赖原生定位模块。本环境仅做了离线和模拟连接测试，实际 Windows 连接仍需本机验证。

输出在 `data/imu_calibration/时间目录/imu.csv` 和 `capture.json`。每 30 秒打印进度，默认采集 30 分钟。10 分钟是当前工具的最低筛选时长，不保证足以辨识随机游走；缺少相应斜率时可能仍需更长记录。

检测到解锁、运动、遥测中断或源时钟回退会终止并保留不合格标记。程序退出只恢复其请求的遥测速率默认值并关闭自身通信，不控制电机。

## 分析

```powershell
python tools/audit_imu_noise.py "data/imu_calibration/实际时间目录"
```

也可以检查已有飞行实验：

```powershell
python tools/audit_imu_noise.py "data/runs/run_20261010_104637_886270"
```

结果为对应目录的 `imu_noise_audit.json`。飞行记录只能筛选静止候选，不自动当作受控静止标定。

也可以不填目录，自动检查最新一次已结束的静止采集（跳过尚未生成 capture.json 的运行中目录）：

```powershell
python tools/audit_imu_noise.py
```

工具会先打印实际选中的输入路径。文档中的“实际时间目录”是占位说明，不应原样输入；路径不存在时会提示如何选择，而不是输出 NumPy 文件异常堆栈。

分析先检查源时间连续性、静止条件、记录长度与采样间隔。当前实现使用标准等间隔重叠 Allan 偏差；不合格的不规则采样不会被强行插值成高频原始数据，也不会输出伪标定值。若专用采集依然明显不规则，下一步应检查 PX4 源数据/日志记录途径，而不是继续提高请求频率。

通过检查后，按每个轴拟合：

- 白噪声：Allan 偏差 = N / sqrt(tau)，斜率约 -1/2。
- 偏置随机游走：Allan 偏差 = K * sqrt(tau/3)，斜率约 +1/2。

仅当六个轴都分辨出两类斜率时，才给出保守的轴最大值噪声候选；仍需回放验证，不自动写配置。短时标准差与固定均值偏置都不能直接当作这四个参数。

公式和单位遵循 [Kalibr IMU Noise Model](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)。该模型的连续时间噪声密度与离散采样标准差不同；消息频率也不必然等于 IMU 内部采样带宽。
