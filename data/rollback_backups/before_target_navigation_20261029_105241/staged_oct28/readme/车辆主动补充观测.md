# 语义物体主动补充观测

直接运行 `python run_explore.py`。无需重新编译 C++。

**当前默认仅识别车辆（car / truck / bus / van）**：`detections/object_detect.py` 的 `DetectorConfig.class_prompts` 与 `semantic_landmark_classes` 都设为 `VEHICLE_CLASSES`。其他类别的实现保留但不参与本次识别、建号或主动补看；以下其他物体流程描述仅供以后重新启用时参考。雷达占据建图与避障不依赖此类别开关。

飞行中记住刚观察到、距离不超过 8 米、尚未补看的车辆。先完成已承诺的探索航点，再停稳转入补看。两次补看之间必须至少成功到达一个新的探索航点，不能连续处理所有车辆而饿死地图探索。短暂离开视野不会丢失待办；选点使用当前地图中的最新车辆几何，车辆超过 8 米则暂不绕远追踪。按车辆已观测包围框外侧生成候选位置，从不同方向选择现有 A* 可达、视线未被地图遮挡的观察点。飞行仍使用原有 A* → EGO → 位置航点控制。选点保持当前高度，补看不主动抬高越障。

到点刹停后才转向车辆，不在途中不断朝向车辆。转向完成后，必须连续收到 `SemanticNavigationConfig.verification_frames` 次不同时间的该车辆新观测，才保存一个有效视角；旧帧和只有到达事件不算。实际表面点云仍由现有实例关联和表面累计模块融合。

`config/exploration_config.py` 中两个参数：

- `object_inspection_views = 4`：单物体最多尝试的观察航点。
- `object_inspection_timeout = 90.0`：单物体总时间预算（包括飞行）。

每个观察点转向后的识别等待复用 `config/semantic_navigation_config.py` 的 `verification_timeout`（默认 8 秒），不再单独配置补看等待时间。单物体 90 秒总预算仍限制整个流程。

首个航点导航失败、到点没有足够新观测、安全可达范围不足、实例消失、达到次数或时间上限时结束补看，继续普通探索。原有全局探索终止条件、返航时间预留仍然有效。不会为了凑满一圈飞进未知空间；四次尝试也不等于完整 360° 覆盖。

本次运行内保留已补看车辆的记忆，并通过 `merged_from` 继承合并 ID 的记忆。HTML 中的 W 航点标为“物体补充观测 vehicle_XX”；`private/exploration_waypoints.json` 保存来源 `object_inspection`、目标实例、是否取得新观测。探索报告及语义图的 `exploration.object_inspections` 保存尝试方向、有效视角、结束原因。尚未关联的两个 ID 不会仅凭距离强行合并。

有效视角表示补充观测成功，不代表已达到厘米级绝对定位精度。雷达/相机时序、外参及建图坐标误差仍会影响结果；需通过下一次仿真检查多视角表面是否重合、重复 ID 是否减少。

## 2026-10-20 实验核查

核查 `run_20261020_165145_649669`：

- vehicle_03 / vehicle_04 先被同帧分配记录为不同实例，后续车身点云发生大面积重叠，但原来的永久否决阻止纠正。现在要求更严格的稳定表面重叠（较小表面至少 50% 的双向支持）、外观一致、三次时序确认，才允许推翻早期分裂；当前同帧仍分别观测到两个实例时继续否决。原始车辆观测回放得到 `04 → 03`，未硬编码这两个编号，也未改写原实验地图。
- W16–W19 周边曾有 vehicle_05 / vehicle_07，平均置信度分别约 0.228 / 0.230，低于正式地图门槛 0.25。新增独立的 `object_inspection_candidates` 帧字段，把已多次观测、尚未达到地图发布门槛的车辆假设交给补看流程；不写入正式语义节点或占据标签。新视角能否提升识别仍需实际飞行验证。
- 补看选择器兼容真实记录中的 `car / truck / bus / van`，不再仅匹配 `vehicle`。

车辆优先观测触发后，原 W 航点状态为 `deferred`，HTML 显示“优先观测车辆，暂缓”。这不计入导航失败或前沿失败重试。补看完成后重新选择探索目标；补看过程不被其他车辆打断，全局探索时间及返航预算继续生效。

## 灭火器、出口与标志牌

车辆以外，消防柜、灭火器、出口门、出口指示牌和交通标志牌也会进入优先观测。灭火器是独立类别 `fire extinguisher`，使用 `portable fire extinguisher` 和 `wall mounted fire extinguisher` 提示词；不把消防柜当作灭火器。它复用安全类物体的置信度与多帧确认门槛，确认后才作为正式地图物体及补看目标。

贴墙物体以第一次可达观察方向为基准，使用 0°、±30°、±60° 的候选侧移方向，仍经 A* 可达性和视线检查。保持飞行高度，不尝试绕墙背面；高处标志若不能进入相机视野，仍会按观测超时退出，不虚报已完成定位。

原来的 `vehicle_inspection_views / vehicle_inspection_timeout` 改名为 `object_inspection_views / object_inspection_timeout`，共用一套预算和执行链路。旧实验输出不改写；新实验报告使用 `object_inspections`。

## 连接视角与位置可信程度（2026-10-21）

- 多次观测到但不足以独立建号的碎片，最多保留 90 秒供连接视角使用。附近恰有一个合理的车辆范围时，仅提出补看假设；多个邻车都合理时不选择归属。
- 连接航点要求现有车身与碎片两块区域均有可见视线，且方位夹角不超过 80°，航点仍经原 A* 与执行安全检查。镜头朝向两区域之间。是否能在真实图像中同时看到，仍以实际观测为准。
- 每辆已有有效补看结果的车最多额外复查一次连接视角，保留之前的有效视角记录；无新观测、导航失败或超时的车辆，本轮不再以连接复查重新触发。碎片不能仅因距离、外观或选中航点而合并；三次新观测必须覆盖两块稳定表面的有效点云区域，才能融合到已有 ID。
- 新 JSON 字段 `position_status`：`partial_surface` 表示位置仍是局部表面估计；`multi_surface_estimate` 表示累计表面的长、宽、高及主方向获得足够支持，采用观测定向包围框中心。`observed_oriented_box` 保存中心、尺寸和航向。不外推未观测车身，也不宣称实际整车中心精确。
- HTML 标签提示位置待完善或多表面估计；语义图节点也保存 `position_status`。正式语义位置与地图标签继续共用同一实例输出。包围框不会被强制填成占据障碍。
- 航点 `connection_view` 标明连接观测；`observation_verified` 只代表收到新识别；只有 `fragment_fusion_verified` 为真，才表示该航段中新增了经过验证的碎片融合。车辆记录的 `connected_fragment_count` 保存已融合碎片数量。

当前依然仅启用车辆识别。无需编译，重启探索程序即可使用；原实验地图不覆盖。历史数据回放只验证关联行为，不能模拟新航点产生的观测。
