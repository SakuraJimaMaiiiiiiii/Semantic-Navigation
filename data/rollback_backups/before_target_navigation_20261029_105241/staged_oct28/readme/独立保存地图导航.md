# 默认启动（最新用法）

```powershell
python navigate_target.py
```

默认独立交互导航、自动打开 HTML、自动选择 `data/runs` 下最近一份完整且已确认返航的探索地图。按 run 目录时间排序；校验 bundle 和缓存摘要，跳过未完成/损坏/无语义物体的地图以及只有导航输出的目录，启动时打印实际选择的目录。没有可用地图则停止并提示，不自动起飞探索。

随后按“请输入导航点”的提示输入一个或多个物体 ID，多个 ID 用空格分隔，按顺序执行。仍要求同场景、同起点，起飞前保留雷达坐标一致性核对。

可选覆盖：`--map "路径"` 手动选图；`--no-open-map` 不打开浏览器；`--config` 指定启动配置。`--standalone` 保留兼容但无需再写。

向已经运行的控制终端发目标时明确使用：

```powershell
python navigate_target.py --client --instance-id vehicle_02
```

`--status`、`--return-home`、`--shutdown` 自动使用客户端模式，不会启动第二个控制进程。

# 不重新探索，直接进行目标导航

先正常完成一次探索并保存 `exploration/bundle.json` 和 `private/navigation_cache.npz`。之后可退出探索进程，用一个终端执行：

```powershell
python navigate_target.py --standalone --map "data/runs/run_20261026_123724_906919/exploration" --instance-id vehicle_01 --open-map
```

`--map` 也接受整个 run 目录。目标还可用 `--class-name vehicle`，或省略两者读取 `config/semantic_target.json`。ID 以所选旧地图为准。

- UE、CopterSim/PX4 和 WebSocket 服务仍需运行；不需要运行 `run_explore.py`。
- 保持同一场景、同一物理起点和初始朝向。启动会核对当前 NED 起点、朝向，以及实时雷达占据点与旧地图的重合情况。它是同坐标系一致性检查，不是任意起点重定位；换场景、移动起点或更改定位基准后不能直接套用旧图。
- 起飞前最多等待 60 秒收集新感知和地图。核对不通过则报错且不开始任务，不自动猜测旋转/平移变换。
- 继续使用原有 A*、EGO 和位置航点控制；目标任务结束后悬停，显式发送返航命令后才返航降落。当前感知会更新地图，旧地图只补充未观测区域；读取旧图不会伪造实时地图时间戳。
- `--config` 默认读取 `config/explore.json`，复用 SAM3 / YOLO-World+SAM2、提示词、SAM3 服务地址和控制端口。独立导航不执行探索，也不启用该文件中的实验性 FAST-LIO，导航坐标仍为 PX4 NED。
- 旧实例 ID 与新检测 ID 不直接相等匹配。目标确认依据类别、包围框重叠和位置的一致性；模糊匹配不报告确认成功。
- 输出位于新 `data/runs/run_.../exploration/`：`map.html`、`source_map.json`、`target_result_*.json` 和导航记录。原地图不会被覆盖。目标任务结束后本进程保持运行，接收后续目标。`--return-home` 返航落地后仍可接收新任务；`--shutdown` 返航落地并退出。
- 旧双终端发送目标需要加 `--client`。`--status/--return-home/--shutdown` 可用于独立导航和探索会话；独立模式不要与旧探索控制进程同时运行。同控制端口占用会阻止第二个进程启动。

本阶段通过离线加载和单元测试，仍需在仿真环境完成首次飞行验证。雷达重合检查不能证明任意场景下的绝对定位正确。

## 连续目标与悬停

第一次使用上面的 `--standalone` 命令启动控制终端。到达并确认目标后，飞机在安全接近点悬停（不是飞到车辆中心）；保持该终端运行。现在默认启用当前终端交互，在 `导航>` 提示符后直接输入：

```powershell
vehicle_02
vehicle_03
home
```

支持一行多个 ID（例如 `vehicle_03 vehicle_01`），依次执行；任务失败则停止本行剩余目标，等待重新输入。输入 `status` 查看状态，`help` 查看帮助，`quit` 返航降落后退出。原先另开终端的命令仍可使用；执行中拒绝新的移动命令，不抢占当前任务。后续任务从当前空中位置规划，不再次起飞，也不改变最初的返航原点。目标未能确认时会明确报告失败并悬停，不把失败当作成功到达。

`--shutdown` 会先尝试返航降落，再退出服务。Ctrl+C 是中断流程，执行异常清理降落，不等价于正常返航命令。只要仍在空中等待，就必须保持控制终端和仿真运行。探索本身仍按原流程返航落地，不会因该修改停在最后一个探索点。

## 交互输入导航点

直接运行 `python navigate_target.py`。完成地图核对后，提示：

```text
请输入导航点（多个物体 ID 用空格分隔，home 返航，quit 退出）：vehicle_03 vehicle_01
```

先导航到 vehicle_03，完成后继续到 vehicle_01；全部完成后悬停，再次提示输入导航点。单个目标也可直接输入。失败则停止本行剩余目标，不自动跳过。输入 `home` 返航降落，`quit` 返航降落并退出。
