# 车辆多视角定位（2026-10-27）

本次沿用已有雷达/深度相机坐标链路、实例 ID 和安全多方向补看流程，改进已经关联的车面几何估计，以及包含旧车面和新车面的连接观测关联。不做检测框中心三角化，不修改 A*、EGO、控制器或占据地图自由/障碍状态。

## 修改

- `mapping/instance_surface.py`：继续使用 0.1 m 体素累积，每帧每体素一次贡献，至少两次观测才用于持久几何。替换受点云分布影响的 PCA 主轴：在水平角度上搜索，由实测车面贴合包围框边缘的程度确定朝向，结合百分位边界计算已观测范围和中心。纯最小面积法可能把 L 形侧面/端面拟合到对角线上，因此不单独用面积作为目标。
- 对已拟合包围框检查实际竖直车面支持，结合已有尺寸要求区分 `partial_surface` 和 `multi_surface_estimate`。前者不宣称已经定位完整车辆。
- `mapping/vehicle_instance_tracker.py`：外观一致且实际覆盖旧稳定车面一定范围的连接观测，可以参与跨视角关联；沿用原来的距离、竞争消歧和 ID 管理。不会仅因颜色一样或位置接近合并车辆。
- `navigation/map_view.py`：对多表面估计绘制同一语义记录中的朝向包围框；旧记录和局部车面仍按原包围框显示。蓝色色块不会被填入导航障碍地图。

## 输出与使用

直接按原方式启动探索，无需 CMake 编译或增加参数。新记录继续通过现有 `vehicle_geometry()` 导出 `observed_oriented_box`、`position_status`，增加 `geometry_fit=measured_face_rectangle` 和 `supported_box_faces`，用于核查模型证据。箱体 yaw 是水平长轴方向，模 π 等价，不代表已经识别车头朝向。

正常的语义实例位置通过 `VehicleTrack.map_position` 使用多表面包围框中心；有效车面不足时仍为局部估计。既有主动补看预算和安全航点保持不变，不强制绕车一整圈。

## 验证与限制

Windows 项目环境 40 项车辆关联/补看/SAM3/独立导航回归及 1 项 HTML 几何一致性测试通过。新增合成测试覆盖旋转的侧面+端面、重复单侧观测、单帧离群车面、连接观测保持 ID、无重叠邻车。

更新了一项原有补看测试的模拟执行接口，使其包含当前平滑路径依赖和 `_move` 的关键字参数，没有修改该测试的任务行为断言。

尚未做 UE 实飞或实际场景精度评估。此次改变不修复雷达/相机位姿误差，也不能解决完全没有有效三维观测的情况；不能承诺消除所有重复实例。旧地图不会因启动程序自动重算。
