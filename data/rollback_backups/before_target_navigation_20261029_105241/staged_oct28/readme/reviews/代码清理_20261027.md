# 代码清理记录（2026-10-27）

## 范围与原则

对 application、config、detections、localization、mapping、mission、navigation、planner、recording、sensors、vehicle、tools 自有 Python 源码做语法/异常处理扫描；阅读主要启动、感知、导航、探索和清理调用链。排除 third_party、构建产物、模型、实验数据及 node_modules。静态扫描不代表全工程的每个分支都已运行验证，也不代表剩余的宽泛捕获都应删除。

按照本次要求：配置和静态输入在所属边界验证，内部信任已建立的对象契约；不要以重复判空掩盖缺失初始化；正常失败用返回值处理；单次顺序逻辑不额外包装；新增低概率防御逻辑前先向用户说明并征求同意。

实时传感器帧、地图版本、飞行状态每次都会变化，其检查不是同一份输入的重复校验。

## 实际修改

- `config/planner_config.py`：用 dataclass 字段遍历替代手写字段名/值清单；保留原参数、默认值和检查语义。
- `navigation/frontier_explorer.py`：在初始化阶段创建决策规划器和 phase；删除懒加载包装 `_decision_planner`，移除对已初始化字段的缺失兜底。
- `navigation/exploration_session.py`：统一初始化 HTML 显示字段；检查点直接读取 FrontierExplorer 的既定属性。
- `navigation/terminal_commands.py`：任务失败使用普通控制分支终止当前批次，不再先抛 RuntimeError 再自行捕获；输入错误仍允许重新输入。
- `detections/sam3_client.py`：只包装连接失败，接口不匹配或解析错误保留真实原因，不再统一误报为需要启动服务。
- `planner/native_ego_local_planner.py`：删除未被调用的 native_available 属性；将一次性扩展加载放回构造函数，仅捕获 ImportError；轨迹规划错误直接上报，正常无路仍返回 None。
- `detections/object_detect.py`：雷达融合计数在构造时初始化；同一目标的地标判断只计算一次。
- `tests/test_native_ego_errors.py`：覆盖原始异常保留、正常无路返回、成功轨迹仍需净空验证。

## 保留的异常处理与检查

- 后台线程记录错误并交由主线程上报，否则线程异常可能脱离任务状态。
- 退出阶段逐项清理，保留原始异常，确保前一项失败不会跳过后续资源释放。
- 网络请求和文件输入的边界检查。
- 持续变化的地图/传感器有效性、碰撞与落地确认。
- 原生轨迹的 Python 净空检查：原生结果可能在 Python 侧改高，后续检查针对调整后的轨迹。

本次未新增低概率容错分支，未修改 A*、EGO 算法参数、障碍距离、实例定位过滤阈值或落地逻辑。
