# 畅通航段执行延迟与转向修复

依据最新 `run_20261028_134600_119625` 的 W1–W11 记录：W1 正常到达；W2/W4/W6/W8–W11 的路径复算畅通、route_clear、无路径拒绝，但命令总耗时 2.8–3.7 秒；W3/W5/W7 是转向超时。

## 修复

1. **在线回环地图健康接口**：`OnlineLoopNavigationMap` 原来没有更新心跳接口，`SemanticNavigator._check_maps` 会退回 `source.snapshot()`。新增 `last_observation_completed_at`，直接读取当前活动地图的完成心跳。健康检查不再为读取时间而构建整张全局快照。
2. **地图心跳读取**：局部/全局地图的完成时间作为独立发布的标量读取，不等待融合写锁。几何快照和融合仍使用原锁，地图超时判定仍生效。健康读取不提供一组几何数据的事务一致性，其用途只是查询最后一次完成时间。
3. **执行后前向复核**：局部地图暴露最新相机前向净空标量。`_FlightGuard.revalidate_plan` 直接读取此值，不再为了一个数重复构建/等待局部占据快照。机身位置、刹停走廊、原已认证栅格、地图健康和回环版本检查保持原用途。
4. **转向按实际时间推进**：`align_yaw` 原来每轮固定按 0.05 秒积分，即使 health_check 已经耗时数秒。现在按上次指令至本次指令的实际间隔积分，并限制本次步长不越过目标航向。最大航向变化速率及到达容差未调大。

本轮针对重复读取与阻塞，不降低障碍距离，不增加超时预算。未改 A* 算法，也未将未知格直接作为自由格。

## 测试

新增四项：在线地图健康读取不取快照且停更仍报错；融合写锁持有期间心跳读取不阻塞；执行复核不重复取快照且新近障碍仍被拒绝；每次健康检查耗时 1 秒时原地转向仍按实际时间完成且不越过目标。
