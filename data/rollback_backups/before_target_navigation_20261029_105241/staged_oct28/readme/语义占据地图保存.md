# 语义占据地图

运行 `python run_explore.py`。正常探索和返航完成后，在本次 `data/runs/run_*/exploration/` 自动保存以下数据；捕获到任务异常时也尝试保存部分地图。进程被强制杀死或断电不保证产生完整导出。

| 文件 | 内容 |
| --- | --- |
| semantic_map.json | 地图入口、坐标系、起点、时间、完成状态、物体实例及其估计位置/包围盒、几何文件索引 |
| private/navigation_cache.npz | 三维稀疏体素 indices、log_odds、resolution、阈值、物体记录、起点，以及逐体素 semantic_labels 和实例查询表 |
| occupancy_2d.npz | 保存时飞行高度的二维 indices/states、考虑水平净空的 safe_indices，以及格子与实例的多对多关系 |
| semantic_graph.json | 不包含绝对坐标的物体属性及相对语义关系 |
| bundle.json | 同会话导航读取入口与三维缓存校验值 |
| map.html | 二维可视化、物体和规划航点 |

所有空间位置使用 world NED：x 北、y 东、z 向下，单位米。三维体素中心为 `(index + 0.5) * resolution`；不是以每个传感器当前位置为原点。语义图仍不暴露坐标，坐标集中在空间地图及私有导航缓存中。

三维 log_odds >= occupied_threshold 为占据，<= free_threshold 为空闲，两阈值之间及未记录体素为未知。二维 states=0 表示完整机身高度带内已观测空闲，1 表示带内存在障碍，缺失格为未知。safe_indices 额外考虑水平净空，不能将所有 states=0 的格直接作为可执行航点。二维投影仅代表文件记录的高度，换高度应从三维数据重新投影。

物体记录保留 runtime_instance_id、class_name、position_world、bbox_3d、confidence 和 observation_count 等已有字段。位置和包围盒仍是感知估计。另有独立的实测表面体素标签，包围盒不改写几何占据，也不用来填充标签。不能把“识别到车的位置”直接当成飞行目标，应通过现有 approach/A* 选择安全接近点。

## 体素实例标签

`semantic_map.json` 版本为 2。感知保留有效 SAM mask 内、经过深度及雷达一致性筛选的世界表面点，用全局地图相同的 resolution 量化。相机与雷达融合保留实测位置，不把表面点平移到滤波锚点，也不吸附到附近障碍。

每个实例在每个体素每帧最多贡献一票；至少两帧且票数严格超过其他实例合计时才确认归属。只输出已确认物体 ID，身份合并后旧证据跟随 `merged_from`。累计证据通过感知快照传递，探索线程跳过中间感知帧不会丢掉已记录表面。分辨率和容量复用 `GlobalSparseMapConfig`，不新增用户参数；容量达到上限时淘汰最久未更新的语义体素证据。

三维缓存中的字段：

| 字段 | 含义 |
| --- | --- |
| semantic_labels | 与 indices 逐行对应的整数标签；0＝未分类，不表示空闲 |
| semantic_instance_ids | 标签索引对应稳定 ID，首项为空字符串；与图节点、HTML ID 一致 |
| semantic_class_names | 同一索引对应 car、column、signboard 等类别 |
| semantic_support | 获胜实例的支持帧数；别名合并使用最大计数，避免重复计票，因而可能低估支持数 |
| semantic_confidence | 获胜实例票数占比，不是定位精度或经过标定的概率 |

只给当前 `log_odds >= occupied_threshold`、且同一体素有上述表面证据的格子赋非零标签。空闲、未知、未观测到语义表面或身份冲突的格子保留 0；所有几何占据值不变。并非每个障碍都一定识别成车、柱子或标牌。现有 A*、EGO 和控制器继续使用原几何地图。

二维缓存的 `semantic_cell_rows[k]` 指向 `indices` 的行，`semantic_instance_labels[k]` 指向文件内的实例查询表。同一 XY 格在高度带内可能有多个实例，关系会全部保留；高于/低于高度带的物体只保留在三维标签中。

## 物体身份与显示位置

同一次运行中，车辆、柱子和交通指示牌在视频、`semantic_map.json`、导航缓存、语义图及 HTML 使用同一实例 ID。过滤未确认目标或低矮柱体后允许编号有空缺，不再把 `column_02` 重新编号成 `column_01`。确认重复实例后保留较早的 ID，并将旧 ID 写入 `merged_from`，历史语义关系及目标查询跟随该别名。相邻物体不会只因为距离近就被合并，同时观测到的不同实例保留独立身份。

语义几何先将 SAM mask 限定在检测框内，再剔除边缘和孤立深度离群点。遇到两个有充分支持、明显分离的深度面时，放弃该帧定位，避免生成前景与背景之间的假坐标。相机与雷达使用相同有效 mask；雷达采集历史与地图积分分别运行，慢积分不会阻塞同步点云缓存。RGB-D 启动时用至少五帧、跨越半秒的同步时间戳估计共享时钟偏移，整次运行固定该偏移；这消除了首帧轮询延迟的影响，但不能代替对传感器传输时延和位姿误差的标定。

`position_world` 是多帧可见表面估计的锚点，并非保证处在完整车辆或柱子的几何中心。HTML 圆点使用这一原始世界位置，只按初始航向转换为屏幕坐标；虚线框显示观测包围框的俯视投影。悬停可查看 NED、高度和观测次数。二维占据图仅显示当前飞行高度带，位于更低车顶或更高指示牌上的语义点可以投影到白色栅格，这不等于坐标错位。物体标记不会吸附到最近障碍格，也不会把估计包围框填成障碍物。

定位先去掉掩膜边缘、深度突变及不能可靠估算法线的像素，再剔除表面法线与视线夹角超过 75° 的点。
中心 ROI 用于单帧位置估计，可靠的完整表面仍用于范围和体素标签，因此不会把柱子的上下部分直接裁掉。
中心 ROI 内有足够且通过时间、投影、深度一致性检查的雷达点时，优先采用这些实测点估计位置；
不会平移深度点云去强行贴合雷达。证据不足的定位不入库。

关联到同一 ID 后，以 0.10 m 网格保存有界的实测表面并集，每帧每格只记一次观测。
至少重复观测两次的格子才参与稳定范围计算；达到 12 个格子后，HTML/语义地图位置采用
该可靠范围的中心，包围框不再随单帧可见车面反复替换。每个实例最多保留 4096 格。
这仍是已观测范围的中心，不是不可见部分的完整物体真值中心。该并集不修改占据状态，
也不凭空间接近自动合并两个 ID；原有歧义拒绝和同帧不同物体约束继续生效。

车辆跨视角关联还会比较实测范围，而不只比较可见表面中心。完整车身与局部车头/车尾的
投影面积相差至少两倍、小范围至少 75% 被共同范围覆盖、且高度重叠达到较小高度的一半时，
允许用强外观一致性恢复原 ID。该分支可以越过可见中心的距离/统计门限，不扩大普通距离门限；
近似平面的投影厚度最低取一个表面格（0.10 m），不会按位置协方差扩大包围框。
缺少共同范围、外观证据不足或同时匹配多个实例时，不会强行选择最近车辆。
对于超出普通关联门限、但有局部包含关系的观测，外观证据不足时暂缓关联，也不立即创建新 ID。

跨视角更新保留更完整的实测范围，直到重复点云更新表面并集，不再把车头包围框平移到侧面的滤波中心。
已有两个 ID 若连续解释同一观测，也可积累重复确认依据，避免因分配歧义永远无法合并。
合并仍要求强外观一致、共同范围、唯一重复伙伴和多帧确认（沿用 `vehicle_confirmation_observations`，
默认三帧）；无有效车辆观测会清空本轮确认计数，同帧明确区分过的车辆不会被合并。
保留较早 ID，并通过现有 `merged_from` 同步语义图、HTML 和占据体素标签。
本次只调整车辆实例关联，不引入 VIO/回环，也不改变 A*、EGO、占据状态或飞行控制。

中心 ROI 比例和最大入射角位于 `detections/object_detect.py` 的 `DetectorConfig`：
`instance_center_roi_ratio=0.6`、`instance_max_incidence_degrees=75.0`。
窄柱、细牌内部像素不足时保留已通过质量过滤的内部支持；大掩膜中心被遮挡时不会改用边缘点填补。
这些规则从下次启动建图起生效，不修改已有运行数据。

HTML 另将有实例标签的占据格着色：蓝色车辆、棕色柱子、粉色交通指示牌，紫色其他/多类别。悬停格子显示稳定 ID、Z 范围和支持数。默认隐藏高度带外的语义体素；勾选“显示高度带外语义投影”后以空心虚线显示，避免把天花板附近的标牌误认为机身高度的障碍。显示与导出使用同一体素标签计算及高度带边界。

### HTML、语义图与占据标签的对应

HTML 的“物体 ID 对应表”直接使用占据标签查询表，列出稳定 ID、类别、当前体素标签码、三维已确认占据体素数和当前高度带体素数。对应关系是：

```text
HTML 物体标签 / data-instance-id
    = semantic_graph.json 中 object 节点的 id
    = semantic_map.json 中物体的 runtime_instance_id
    = 三维文件 semantic_instance_ids[semantic_labels[体素行]]
    = 二维文件 semantic_instance_ids[semantic_instance_labels[关系行]]
```

二维关系行用 `semantic_cell_rows` 定位实际格子。数字标签码是每份文件内的查询表索引，不能跨快照当作物体 ID；新物体加入或实例合并后，必须读取该文件自己的查询表。同一物体的长期对应使用字符串 ID，并限定在同一 session/map 内。

点击物体圆点、文字、包围框或表中 ID，会同时高亮同一实例的标注和占据格。一个投影格包含多个实例时，重复点击可轮流查看。高亮会在本地图刷新时保留；已合并或已移除的 ID 不继续高亮。此操作仅用于查看，不发送导航目标。高度带外的语义格仍需勾选对应显示选项。

没有确认体素的物体仍列在表中，数量显示 0，不填充包围框制造占据。`W1/P1` 是探索目标/路线航点编号，不是物体 ID。车辆、柱子、指示牌的跨文件合并回归测试验证旧 ID 被解析为保留 ID，图边、HTML 和二维/三维标签均一致。

这些修正对新采集的数据生效，不改写旧运行的物体位置或编号。重新启动 `python run_explore.py` 即可，无需重新编译 C++。精度应在 UE 中对照同一物体从不同方向的观测验证，不能仅以重复点减少判断绝对定位准确。

## 离线读取（不控制飞机）

```python
from pathlib import Path
import json
import numpy as np

root = Path(r"E:\files\Semantic Navigation\data\runs\run_XXXX\exploration")
semantic = json.loads((root / "semantic_map.json").read_text(encoding="utf-8"))
for obj in semantic["objects"]:
    print(obj["runtime_instance_id"], obj["class_name"],
          obj["position_world"], obj.get("bbox_3d"))
with np.load(root / semantic["occupancy_3d"]["file"], allow_pickle=False) as data:
    occupied = data["log_odds"] >= float(data["occupied_threshold"])
    occupied_centers = (data["indices"][occupied] + 0.5) * float(data["resolution"])
    if "semantic_labels" in data:  # 旧地图没有此字段
        labels = data["semantic_labels"]
        known = labels > 0
        centers = (data["indices"][known] + 0.5) * float(data["resolution"])
        instance_ids = data["semantic_instance_ids"][labels[known]]
        classes = data["semantic_class_names"][labels[known]]
        for center, identity, category in zip(centers, instance_ids, classes):
            print(center, identity, category)
with np.load(root / semantic["occupancy_2d"]["file"], allow_pickle=False) as data:
    safe_cells = data["safe_indices"].copy()
```

现有 `load_bundle(directory, session_id)` 返回物体 records、occupancy_map 三维栅格，以及新地图的 semantic_voxels 标签字典。旧缓存仍可读取，不伪造旧地图的标签。当前保存目标导航继续使用缓存物体和实时地图进行接近规划，不自动用历史空闲区覆盖实时障碍。

空间地图可以跨程序读取分析；控制导航仍要求原会话、返航确认和校验通过。重启仿真或改变起点后，需要先将当前定位重定位到保存地图坐标系，不能直接沿用旧 NED 坐标。未完成探索/返航的地图不宣称全图覆盖，也不会因此解锁导航。

验证：体素证据、身份关联、保存/读取回环、HTML、高度投影、相机雷达支持点和探索/导航工作流，共 132 项测试通过；缺少 torch 的运行时配置测试排除 1 项。当前 Linux 环境未加载 Windows 原生 FUEL 模块，相关工作流测试使用 Python 前沿后端；未进行 UE 飞行验证。无需重编译 C++。

## 语义图格式 v2：nodes / edges

`semantic_graph.json` 和 `semantic_graph.partial.json` 统一使用图结构，不再输出旧版 objects/relations/places/connections 四组列表。物体节点 type=object，属性放在 attributes；观察位置节点 type=place。节点不包含绝对坐标，空间位置仍通过相同实例 ID 查询 semantic_map.json。

```json
{
  "version": 2,
  "directed": true,
  "nodes": [
    {"id": "vehicle_01", "type": "object", "attributes": {"class_name": "car", "color": "red", "confidence": 0.9}},
    {"id": "column_01", "type": "object", "attributes": {"class_name": "column", "confidence": 0.92}},
    {"id": "place_0001", "type": "place", "attributes": {}}
  ],
  "edges": [
    {"id": "vehicle_01:near:column_01", "source": "vehicle_01", "target": "column_01", "relation": "near", "symmetric": true, "distance_m": 2.1},
    {"id": "vehicle_01:observed_at:place_0001", "source": "vehicle_01", "target": "place_0001", "relation": "observed_at"}
  ]
}
```

边类型包括 near、in_front_of/behind、left_of/right_of、above/below、co_observed、observed_at、traversed_to。同一对节点可以有多种关系，按多重图读取。near 和 co_observed 带 symmetric=true，一条边表达双向关系；其他方向边解释为 source 相对 target 的关系。前后左右仍以起飞初始航向为基准。

边 ID 由 source、relation、target 组成，所有边端点都对应节点。跨次运行的实例 ID 不保证表示同一物体，map_id/session_id 用于区分地图。已有历史 JSON 不会自动改写；重新运行后生成 v2。目标导航仍通过私有 records 读取位置，不依赖旧版图的 objects 字段。
