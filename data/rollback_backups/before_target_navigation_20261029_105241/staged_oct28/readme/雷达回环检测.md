# 雷达回环建图与在线导航

运行 `python run_explore.py` 自动启动雷达回环检测、后台位姿图优化和语义回放，不需要重新编译。

## 实时显示

唯一在线页面是 `exploration/map.html`，直接显示校正后的占据地图、语义标签、飞机、A* 路线和 W 航点。首批数据完成前显示等待状态。没有有效回环时使用恒等校正。

飞机和当前路线使用显示版本的最新校正变换；历史 W 点按首次记录该位置时的雷达时间戳插值校正。页面每 2 秒刷新；后台每轮完成后等待 10 秒，几何更新延迟还包括重建耗时。在线 revision 只保存数据，不生成额外 HTML。旧实验页面不自动删除。

## 检测和导航

位移关键帧 → 历史邻近位置搜索 → 确认真正离开后重访 → 降采样 → 刚体 ICP → 双向重叠、残差、退化和校正幅度检查。原地旋转不算重访。

有效约束进入四自由度位姿图，固定首帧，优化平移和 yaw。历史点云和原点一起校正，再投射射线重建占据/空闲证据。语义观测先变换，再重新关联实例，生成同版本图节点和体素标签。

在线导航把校正后的历史几何转换到当前 PX4 NED，补入重建期间的新雷达观测后整体切换。探索与返航 A* 使用该地图，EGO 继续检查实时局部地图，控制器仍接收 PX4 航点。切换后旧路径重新规划，旧 EGO 缓存失效；执行前版本变化会拒绝旧规划结果。无有效回环时使用原始实时地图。

历史补算在共享锁外执行，锁内只取队列和切换地图。最多追赶 8 轮；观测丢失或跟不上实时数据时拒绝本次切换，保留当前导航地图，不放宽地图超时检查。

## 参数和诊断

关键帧、ICP、位姿图参数在 `config/global_map_config.py`。雷达关键帧达到 `max_keyframes`（默认 500）后停止增加；旧深度回环入口的 `loop_closure_enabled` 不控制雷达检测器。

- `maps/lidar_loop_closures.json`：检测器关键帧、约束和错误。其 `map_correction_applied=false` 仅表示检测器本身不修改地图，在线应用结果看下一项。
- `maps/live_loop_corrected/status.json`：`online_navigation_applied`、`navigation_revision`、关键帧数、回环数、处理截止时间及耗时。`waiting_for_semantics` 不阻止几何地图参与导航。
- `maps/live_loop_corrected/latest.json`：最新完整版本目录。
- 各 `revision_*`：同步语义图、语义占据标签和导航缓存，保留供诊断。
- `maps/lidar_loop_keyframes.npz`：检测器正常关闭后保存的原始关键帧存档。

## 离线重建

正常结束实验后，可执行：

```powershell
python tools/rebuild_lidar_loop_map.py "data/runs/本次运行目录"
```

输出到 `maps/loop_corrected`：原始关键帧重建对照、校正地图、关键帧变换、报告及独立版本的语义地图/HTML。需存在关键帧存档；只有约束 JSON 无法重建。语义同步重建还需 `maps/semantic_observations.jsonl`。

离线版本内部 HTML、图节点和占据标签使用同一 ID；车辆编号从 1 开始压缩，映射写入 `vehicle_id_mapping.json`。在线版本不每轮压缩编号，允许过滤后的空号。回放重新关联可能改变身份，不能直接把回放 ID 当作视频 ID。

每个新版本还保存 `source_identity_mapping.json`，记录校正地图 ID 对应的原始检测 ID 及有效关联观测次数。HTML 物体提示中显示“原始识别ID”；语义记录保存 `source_runtime_instance_ids` 和 `source_identity_observations`。这些字段用于追溯身份，不会按编号强行合并车辆；待确认阶段尚无 ID 的观测不计入对应次数。

## 边界与验证

探索确认返航落地后，会完成一次最终保存并停止 RGB-D 录像、检测视频、逐帧语义日志、规划投影和后台回环重建写入。终端处于 READY 等待状态时不再持续增加 `data` 文件；相机、雷达、感知及内存占据图继续更新，以便接收后续导航指令。后续主动执行目标导航仍会更新任务结果与地图标注，但不恢复探索录像。关闭终端不会再次保存已结束的雷达关键帧存档。

最终保存会在语义日志和关键帧停止采集后，再同步完成一次校正重建，以纳入最后观测中的实例合并。不能仅取消后台任务后直接进入 READY，否则 HTML 可能保留上一版本的重复 ID。该步骤可能延长结束等待时间；完成后不再启动后台重建线程。

两次优化之间仍依赖 PX4 位姿，不是每帧雷达定位；返航落点沿用 PX4 起点判据。在线语义目标接口仍使用 PX4 检测结果，未切换为离线回放 ID。校正地图坐标为 `loop_corrected_ned`，不可作为新会话的 PX4 地图直接加载。

探索中升高避障后，若当前高度的返航 A* 无路，会检查原探索高度的已知安全路线和当前位置的垂直机体通道。两者均通过才以不超过 0.15 m/s 恢复原高度；下降时持续复查地图、碰撞与垂直净空，未知或占据即停止。恢复后重新配置 EGO 平面、重新运行 A*，并同步最终二维地图的高度。每次返航最多尝试一次，不缩小净空、不把历史轨迹强制标为空闲；失败诊断使用 `return_height_recovery_failed`。

重复车库结构可能产生歧义，较大位姿漂移可能使邻近搜索漏检。表面点采样、四自由度模型和回环误配会影响精度。后台完整重建仍可能较慢，需观察积分耗时、位姿同步拒绝数和实时地图新鲜度。

```powershell
python -m pytest -q tests/test_lidar_loop_detector.py tests/test_lidar_loop_map.py tests/test_loop_semantic_replay.py tests/test_live_loop_mapping.py tests/test_online_loop_navigation.py
```

## 车辆优先观测

安全门与消防柜出现近重合的同尺寸表面时，内部保留两类假设，地图与视频只发布持续占优的一类。需要至少 3 次观测、累计置信度证据超过另一类的 1.25 倍，并在 3 个新的相关观测时刻持续占优；接近平票时暂不发布。相邻或尺寸明显不同的对象不按此规则合并。导出记录和语义图保存 `classification_status`、`category_evidence` 及 `merged_from`，占据标签沿用同一别名映射。该策略解决重复分类，不代表已通过真实场景验证最终类别。

消防柜和安全门另有误检门槛：`DetectorConfig.safety_landmark_min_confidence=0.30`，`safety_landmark_min_observations=8`，视频正式 ID 仍需满足已有显示次数门槛。YOLO 原始框标注为 `[candidate]`，SAM 分割画面不显示未确认的这两类。地图仅接受观测高度 1.5～3.2 m、水平跨度 0.55～2.5 m 的门，以及高度 0.4～2.0 m、水平跨度 0.3～1.8 m 的消防柜。尺寸是局部观测范围，遮挡时可能延迟确认；不能单靠门形状证明它是安全出口。默认提示词移除了泛化的 `exit door`、`fire cabinet` 和 `fire equipment cabinet`，保留更具体的出口门、消防软管柜与消火栓柜提示。

视野中有车辆时，SAM2 默认 6 个名额中最多 5 个优先连续分割车辆；剩余名额轮转其他车辆和地标。有效车辆观测尚未确认 ID 时，探索直行及 EGO 可执行轨迹的速度上限降为巡航配置的 60%，不会超过避障自身更低的限速；没有新鲜的待确认车辆观测后恢复。不会因为检测框直接改变航点或飞向车体。

车辆待确认窗口按有效观测间隔调整（2～15 秒），仍要求多个不同时间戳的有效观测。空帧、无效碎片、过期观测不直接增加确认次数，原有几何、外观和置信度检查保留。

已有车辆实例的重复合并证据也使用该时间窗口，避免低识别帧率下证据始终在下次观测前过期。仍须满足几何与外观证据、多次确认及不同车辆排除条件。

车侧与车端仅局部重叠时，还检查重复观测支持的公共表面：在原有 15 cm 容差内，两侧至少各有 24 个匹配体素，较少匹配数达到较小点集的 25%，且公共部分至少两个坐标方向跨度达 30 cm。此证据还须通过外观一致、包围框重叠、中心距离、多个时刻确认、唯一候选及同帧独立车辆排除检查；不会仅凭接近或同色合并。

未匹配的薄车面若与已有车辆外观相符、横向及高度重叠且距离合理，会暂存为待关联表面，不立即发布第二个 ID。连续多个连接视角同时支持已有车辆和该表面后才导入表面并集；重复的同帧一对一独立检测可以解除待关联状态、确认独立车辆。长期没有证据的待关联表面过期丢弃。因此缺少连接视角的车辆可能延迟标注，不能仅凭同色或距离确认身份。

小车面的中心不会拉动已建立的较完整车辆定位锚点；较完整的新观测仍可改善初始局部定位。JSON 中 `anchor_position_world` 保存滤波锚点，`position_world` 继续使用已有表面范围中心供地图显示，`supported_surface_voxels` 表示重复观测支持的表面体素数量。`geometry_representation=observed_surface_union` 及 HTML 提示明确包围框只是已观测范围，不是推断出的完整车体。ROI 与边缘、入射角过滤沿用现有实现，待关联几何不改变导航占据状态。

语义回放不再截断于最后一个雷达关键帧：每轮固定日志文件当前字节边界，仅处理完整行。最后关键帧之后的观测暂用最近一次校正变换；后续回环重放时再更新。因此悬停时新确认车辆也可以加入 HTML 和语义图。该时间外推依赖两次校正之间的 PX4 位姿，不代表获得了新的精确定位。
