# WildOS 图驱动探索入口

## 连续目标的固定图高度与恢复

独立导航的各次目标任务统一使用保存图高度，不再把每次任务开始时的实测高度当作
新的规划平面。飞机已经在空中时，偏差超过 guided_z_tolerance、但不超过 0.5 m，
仅在当前位置到图平面的整个机身垂直通道已被局部三维地图观测为空闲，且不在车辆
禁入投影内时，才允许先停稳、恢复图高度，再重新生成图路径。每次恢复运动指令前
重验最新局部三维净空；未知、障碍、超范围或坐标系变化都不会绕过检查。
地面起飞配置与图高度不匹配仍直接拒绝，错误信息包含当前 NED 高度、图高度、偏差
和容差。恢复事件记录为 WILDOS_GRAPH_HEIGHT_RECOVERY，下图显示恢复阶段及实际轨迹。
返回结果中的 flight_started 表示会话是否已在空中，不能据此判断当前请求已经起飞。

## 目标导航的图路径执行与显示（2026-11-12）

目标导航使用 Dijkstra 生成图节点链，按节点顺序逐段执行，取消跨图拐角的圆滑路径。
图边内仍可细分短航点；在图节点处停稳，再执行下一段。已在到达容差内的起始接入点，
只有当前位置到下一节点通过碰撞检查时才可跳过。起点接入与车辆安全接近点连接属于
经过检查的临时连接，不把车辆中心或语义关联边当作通行路径。

同一个 map.html 的下方图显示：紫色图路径与选中节点，橙色虚线起终点接入段，
青色当前执行航段，红色实测飞行轨迹，深色圆点实时位置。图中列出目标 ID、节点链、
阶段与控制状态。飞行健康回调约每 0.5 秒采样显示数据，浏览器约每秒拉取；图结构
版本未变时也更新位置与路径，刷新保留缩放、平移及图层设置。

局部避障和实时安全检查继续生效，实测轨迹可以偏离计划图边，红线不会吸附到图上。
返航仍沿用原返航规划；开始返航时清除去程路径高亮并标明返航状态，不宣称返航已改成
Dijkstra。每个目标的规划路径保存在 private/navigation_<job>.graph_route.json，
执行状态及最近 4000 个显示轨迹采样保存在同目录的 .navigation.json。最终地图也
保留路径快照；实时更新请使用程序自动打开的 HTTP 页面，file:// 页面只有保存快照。

## 独立图导航与终端输入（2026-11-10）

WildOS 探索确认返航落地并保存后，默认自动退出，关闭本次启动的 SAM3、感知、相机和建图后台；无需保持探索终端运行，也无需重新探索。只有显式添加 `--keep-session` 才保留旧的长期待命控制端。
与原 navigate_target 相同，启动 WebSocket 和相同 UE/RflySim 场景，将飞机恢复到
建图时的起点、初始朝向，然后直接运行：

```bash
python navigate_wildos_target.py
# 也可明确指定保存的 run 或 exploration 目录：
python navigate_wildos_target.py --map data/runs/run_20261110_134324_720694
```

默认先检查已有控制会话；没有运行中的控制端时，自动选择最新有效 WildOS 存档，读取 config/explore.json 的感知及端口
配置（包括 SAM3）。启动时先复核 bundle 返航状态、缓存校验和、图的来源坐标系及
节点/边几何，再核对实时雷达与旧地图是否符合“同场景、同起点”的条件。不是通用重定位；
校验失败不会进入目标飞行。启动本身不执行探索，也不因没有输入目标而自动起飞。

看到输入提示后，可输入 `vehicle_02` 或 `vehicle_03 vehicle_01`。
多个 ID 按输入顺序执行，前一个失败则停止本行后续目标；目标到达后悬停等待下一指令。
可在一行末尾添加 `home`（或 `返航`），例如 `vehicle_01 vehicle_06 vehicle_05 vehicle_03 vehicle_04 vehicle_02 home`，目标完成后自动提交返航降落。目标已明确失败时跳过剩余目标，但保留末尾显式要求的返航；控制端仍会检查是否允许返航。任务状态未知、等待超时或停止客户端时不会抢占任务发送返航。
目标执行期间默认隐藏常规过程打印和进度条，完成后仅输出一行，例如 `vehicle_05：导航成功` 或 `vehicle_05：导航失败（原因）`。不再把图节点链、NED 坐标、APPROACH 事件或完整结果 JSON 打印到终端；这些信息继续保存到本次运行的 `exploration/private/navigation_<job>.json` 及路径文件中。后台故障提示和显式 `status` 查询仍可用于排查。
`status` 查看状态，`home` 返航降落，`quit` 返航降落并退出控制会话。
ID 以所选存档为准，不支持任意自然语言地点描述。跨运行感知 ID 通过几何关联确认，
不会把新旧会话同名 ID 直接视为同一车辆。

图路径采用保存节点与 Dijkstra，运行时仍检查最新占据地图与车辆约束。新的定位版本
或不匹配的飞行高度会阻止继续使用旧图。新结果、上下地图、图副本和来源哈希全部写入
新的 data/runs/<本次运行>/exploration/，原探索存档保持只读。

若探索或另一个独立导航控制端仍在运行，同一命令会自动连接它，无需增加模式参数；已保存的旧会话连接被拒绝时，则加载保存地图独立启动：

```bash
python navigate_wildos_target.py
python navigate_wildos_target.py --status
python navigate_wildos_target.py --return-home
```

自动检测只查询状态；超时、认证失败或会话不一致时停止并提示，不另建控制进程。旧的 `--client` 参数仍兼容，但不再显示在帮助中。显式 `--map` 或 `--standalone` 使用独立模式，端口已被占用时不会另建无人机连接；可省略这些参数自动连接原控制端，或先让原控制端返航
退出。客户端 Ctrl+C 只关闭输入端，不会取消已提交任务；独立模式退出则执行原有
落地和资源清理流程。--wait-timeout 用于客户端等待任务结果。
--instance-id、--class-name、--target 仍支持指定初始目标；配置文件需要显式指定：
`python navigate_wildos_target.py --target config/semantic_target.json`。

## 2026-11-09：墙边起步与目标失败归因修正

新生成的图路径也立即检查已到达的中间接入点：水平距离在 arrival_tolerance
以内、竖直距离在 guided_z_tolerance 以内，并且当前位置到下一节点通过车辆约束
规划地图的线段检查，才跳过该点。不会跳过最终目标，也不会跨越未通过检查的拐角。

实际出发方向与当前航向相差超过 15 度时，先停稳，保持位置进行限速转向。
转向前及过程中以最新局部执行快照复查机身净空、健康状态和坐标系版本；转完后
重新检查路径。前向平移急停阈值没有降低，随后移动仍使用原执行证书和局部避障。

执行前路径失效时，同一次 W 最多重新生成一次图路径，失败过程保存在 replans。
起步位置未离开到达容差范围即持续急停时，failure.scope 记为 departure_blocked；
路径复查失效记为 route_revalidation。两者保留历史 blocked 记录，但不增加目标
本身的失败次数。后者有冷却期；前者还暂停选择其他远处目标，等待本地可通行格、
位置、朝向或前向净空条件变化，再经正常选点、规划和执行检查重试。沿用原有有上限
的恢复观察、任务时间及返航预留预算，不将等待解释为探索完成。

新逻辑仅作用于重启后的 WildOS 探索。原始 explorer、飞控、返航控制器文件未修改；
已经运行中的 Python 进程不会热加载修复。历史运行数据与 W 状态不回写改成成功。
离线保存路线复核见 reports/wildos_graph/departure_20261109/saved_routes.json。

启动入口：项目根目录的 `run_wildos_explore.py`，与 `run_explore.py` 同级。功能实现保留在 `exploration_wildos/explore.py`。原 `run_explore.py`、`navigation/frontier_explorer.py` 和 `navigation/exploration_session.py` 没有修改。新增入口继承现有探索循环，替换候选选择与探索路径来源，独立组装运行会话。

## 运行

在项目根目录、原来可以运行探索的 Python / RflySim 环境中执行：

```bash
python run_wildos_explore.py --sam3
# 使用原 SAM2 后端：
python run_wildos_explore.py --sam2
# 只查看参数，不连接模拟器：
python run_wildos_explore.py --help
```

探索默认同时检测车辆和车库结构柱，SAM3 与 SAM2 后端使用相同类别。柱子按多帧观测关联为 `column_01` 等稳定 ID，通过至少 3 次观测、可观测高度至少 2.2 m、竖直长宽比至少 1.2 的过滤后，写入 `semantic_map.json`、`semantic_graph.json` 和导航缓存，并显示在 `map.html` 的上方语义地图中。无需额外参数；探索入口直接读取 `DetectorConfig` 的默认类别。

支持原入口的超时、最大半径、观察点数量、覆盖停止条件、返航预留时间和端口参数。运行新入口会实际启动原来的起飞、探索、返航、落地和目标导航服务；不能与原探索入口同时控制同一会话。此次开发验证没有启动这些飞行动作。

## 探索中每一步做什么

1. **建立新会话。** 使用当前 PX4 原始占据地图和同坐标系的车辆观测。重新创建图，不把以前运行的图或回环修正显示图直接用于本次飞行。
2. **等待停止再规划。** 沿用原制动与位置保持逻辑。图更新在独立 spawn 进程处理固定快照，不再与雷达融合共享 Python GIL。主线程继续检查任务时间、感知、地图与遥测健康。构图最长等待 30 秒；异常或结束时先终止并回收子进程，结果未通过健康复查不会发布给飞行控制。
3. **准备规划地图。** 融合当前全局与局部占据证据，保留原净空要求和最大探索半径；将车辆观测框的整个水平投影设为跨高度禁入区，禁止越顶。车辆本身不作为可通行节点。
4. **增量更新图。** 保留稳定节点 ID 与历史探索半径，更新自由半径，删除失效节点，维护前沿点归属及生命周期，重新检查边。几何未改变时复用结果。高度、坐标系版本变化时重建图 epoch，取消旧 epoch 的目标。
5. **压缩规划图。** 继续使用此前的节点压缩与稀疏连边；采样历史单独保存。保留前沿节点、锚点、覆盖和连通分量，限制压缩后的路径绕行比例。
6. **生成候选。** 仅从仍有关联未知前沿、且机器人能沿有效图边到达的节点产生目标。排除失败冷却中的目标，以及已观察且没有新增关联未知格的目标。
7. **选择目标。** 默认评分为 `新增关联未知格面积 / (1 + 路程 + 2 × 重复路程 + 转向代价)`。实际平移方向用于保持推进方向，相机转向不改变该方向；转向代价为 `viewpoint_spacing × (1 - cos(起步方向夹角))`。同一位置附近（默认 3 m）、相近观察朝向（45°内）的历史前沿不重复计为新增，节点换 ID 仍保留该空间记忆。不同视角或真正新增的未知格仍可入选；观察朝向指向新增前沿。此评分是项目实现，不是论文 ExploRFM。
8. **生成图路径。** 用经过碰撞检查的短连接将机器人接入图，再按 `边长 + 2 × 已飞通道长度` 加权 Dijkstra 得到节点序列。加权路线的物理长度最多为同图最短路的 1.5 倍，超过时使用最短路，避免为少重复而大绕圈。已飞通道来自实际位置反馈，规划路线不会预先标为已飞；必要的尽头回溯和跨分支通行仍允许。坐标系或高度 epoch 改变时清空该记忆。不会在图不连通时偷偷改成直飞目标或全程 A*。目标失效后返回外层循环重新选点。
9. **执行与复查。** 沿用原航点游标、运动超时、EGO 局部规划、执行证书和最新占据证据检查。运动前再次检查路线；局部绕障实际要执行的线段还要通过车辆几何检查。原有安全检查不会被该检查替代。
10. **到达并观察。** 停稳、确认局部净空后转向关联前沿，更新感知与访问记录。保留原有车辆补充观察流程；补充观察仍可能使用原 A*，它与前沿探索目标明确区分。
11. **继续或结束。** 保留原覆盖增长复查、预算、失败冷却和空前沿多次确认。没有可达图目标不等于探索完成；没有归属或尚未观察的边界仍计入剩余前沿。
12. **返航并落地。** 沿用原任务控制器的返航、落地与回家确认。图探索结束并不直接写成“已返航”。

## 每次运行保存在哪里

每次探索默认录制图探索视频 `graph_exploration.mp4`，与 `map.html` 同目录。画面仅包含规划图、前沿点/前沿节点、车辆轮廓、无人机当前位置及有限轨迹，采用 1280×960、10 FPS 的 MP4；不依赖浏览器窗口，也不启用 RGB-D 或 SAM 检测视频。起飞任务调用前启动，持续覆盖探索、返航与降落，确认落地后立即停止并释放编码器，再进行最终地图整理。保留控制会话时后续导航也不会重新写入这份视频；异常会关闭编码器并保留已录片段。没有逐帧图片目录或帧队列，编码只读取最新图快照。

```text
 data/runs/<本次运行>/exploration/
 ├─ map.html                         上：原始探索地图；下：本次规划图
 ├─ exploration_report.json         探索结果与执行事件
 ├─ private/exploration_waypoints.json
 │                                  目标来源、状态、实际图节点路径
 └─ navigation_graph/
    ├─ last_route.json               最近一次图路径
    └─ update_000001/                后续更新依次编号；仅保留最近两份完整快照
       ├─ graph.json                压缩后的实际规划图
       ├─ graph.html                当时图快照，可单独查看
       ├─ validation.json           拓扑与车辆几何检查
       ├─ incremental_state.json    完整采样历史与前沿生命周期
       └─ planning_grid.npz         当时的已知、障碍和安全格集合
```

上下两幅图使用同一 PX4 坐标基准，均可独立缩放和平移。页面文件在检查点更新；为保留缩放视角，目前浏览器不会自动整页刷新，查看新快照需刷新页面。`planning_grid.npz` 是诊断快照格式，不是允许直接恢复飞行的导航缓存。

## 与论文一致的部分及适配

- 使用前沿节点承担探索目标，图路径实际参与航点生成。
- 在线每轮采样上限调整为 128 次，总采样节点预算 1500，用于控制启动与增量更新开销；这是相对论文每轮 1000 次采样的实时性适配。自由半径上限 4 m、候选连边距离 8 m、距离场阈值 0.5 m、历史探索半径和前沿生命周期保留。离线构图入口仍保留原论文采样数量。
- 继续采用此前确认的紧凑节点、稀疏边，因而实际连边不是论文半径内全部连接。
- 使用当前项目的二维高度切片和车辆三维几何约束；这一入口固定图高度，不沿用探索中的自动抬升换层。
- 更新发生在停稳后的选点和路径重规划处，不是每个控制周期都重新构图。
- 没有实现论文完整 ExploRFM、任务语义评分和辅助目标机制，不应称为论文全系统复现。

## 2026-11-05 起飞后持续悬停修正

## 飞行中的图更新（2026-11-06）

从可安全直达且位于连边范围内的节点中选择最近节点作为当前接入点。
这是机器人与图的关联变化，不移动环境节点，也不为每个定位样本创建节点。
实际频率受健康检查调用频率与地图处理耗时影响，不是硬实时保证。

同时最多运行一个后台任务。等待线程不访问飞控与传感器，数值构图仍在
独立 spawn 进程执行，30 秒超时后终止。后台结果仅在基准图版本与坐标系
仍一致时采用；前台重新规划和任务退出都会关闭后台工作进程。
飞行中继续使用原来的局部执行检查；更新图不直接发送飞控指令。

`navigation_graph/robot_attachment_live.json` 保存最近位姿、接入节点及图版本。
`map.html` 和 `update_*/graph.html` 仍是检查点快照，不是浏览器实时动画。
Dijkstra 在重新规划时使用更新后的图；并非每次后台图更新都立即切换航线。
论文的视觉语义评分、辅助目标节点与本项目图简化差异仍然存在。

## 增量节点取舍（2026-11-06）

在线默认启用 `GraphConfig.incremental_cleanup=True`，属于面向本项目的策略适配，
不是论文 Algorithm 3 原样复现。离线默认仍为 False。

- 同一轮已接受的新节点也参与安全圆排斥，减少新区域成批出现的近邻冗余点；
  并非要求圆不重叠，也不使用固定最小距离。
- 每次更新重新判断前沿身份；旧前沿成为普通节点后，可参与覆盖与连通性检查后删除。
- 精简后的路径修复可能同时恢复多个备选点。现在增加最终清理，针对原始图的
  最短距离矩阵验证 1.2 倍路径上限，同时精确保留安全格中心覆盖与连通分量。
  后续边稀疏化仍另行执行，不能把 1.2 倍当作两阶段合计上限。
- 从活动图退休的冗余节点同步移出增量采样节点集，避免下轮原 ID 再次出现，
  并释放节点预算。它们的历史探索圆单独存入 `explored_memory`，用于抑制
  已探索区域的伪前沿，不再作为路由节点，也不据此把未知栅格改成自由栅格。
- 具有独有安全覆盖、关键通路作用或仍为前沿的节点不会仅因相邻而删除。

离线审计命令：

```bash
python -m exploration_wildos.audit_nodes SNAPSHOT_DIRECTORY OUTPUT_DIRECTORY
```

源目录需包含 graph.json、incremental_state.json、planning_grid.npz。
输出新目录内包含逐节点审计、图预览和退休后的状态，不覆盖历史飞行记录。

## 探索后的车辆图导航

新增根目录入口 `navigate_wildos_target.py`，默认连接正在运行的 WildOS 控制终端。
原 `navigate_target.py` 保持不变。该入口不启动第二个飞控进程，不提供独立加载旧图起飞模式。

终端一：

```bash
python run_wildos_explore.py --sam3
```

等待探索结束、返航落地，并保持终端一运行。在终端二执行：

```bash
python navigate_wildos_target.py --instance-id vehicle_02
python navigate_wildos_target.py --status
python navigate_wildos_target.py --instance-id vehicle_04
python navigate_wildos_target.py --return-home
```

也支持 `--class-name vehicle`、`--target <目标JSON>`、`--no-open-map`。
默认会话描述是 `data/wildos_exploration_session.json`；可用
`--session data/runs/<本次运行>/exploration/session.json` 指定会话。
车辆编号取本次探索最终的 semantic_map.json，不能沿用其他运行的编号。

导航流程：

1. 起飞前确认控制会话、原始 PX4 坐标系、传感器时效及目标实例有效。
2. 在原有距车体表面一定距离的候选观察点中，寻找具有图路径的安全接近点。
3. 当前位置接入可安全直达的最近节点；接近点接入可达且可直达它的最近节点。
4. Dijkstra 在经过当前地图重新验证的图边上搜索；两端连接受连边距离上限约束。
5. 沿图路径生成上层航点，继续使用已有圆角路径、局部避障、运动检查和到达验证。
6. 到达后悬停，允许继续提交下一目标；视觉确认与仅到达地图接近点仍分别报告。

车辆语义节点及车框内部不作为飞行终点。车辆投影全高度禁入；语义关联边不当作通行边。
图不连通时不会回退到栅格 A*。坐标系在飞行中失效属于飞行故障，交由既有异常处理流程处理，
不会误报成“起飞前目标未找到”。`--return-home` 沿用原有车辆约束返航流程，其全局规划仍为原返航算法。

目标任务输出位于本次运行的 exploration/private/：

- `navigation_<任务ID>.graph_route.json`：最近一次上层节点序列与接近点。
- `navigation_<任务ID>.json`：完整执行结果、轨迹与图路径记录。

exploration/ 下的 `target_result_<任务ID>.json` 记录到达、视觉确认、是否悬停等结果。
客户端自动打开同一实时 map.html；上图显示选择的接近点与路线，下图继续显示图与机器人接入点。
